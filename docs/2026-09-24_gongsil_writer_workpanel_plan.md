## 0. 한 줄로

**초안이 완성되는 자리를 "AI 탭"에서 "작업창"으로 옮긴다.**

지금은 AI가 글을 쓰면 곧바로 공실뉴스 기사쓰기 폼으로 넘어간다. 그 사이를 끊고,
오른쪽 작업창 안에서 **읽어보고 · 고치고 · 사진을 붙인 뒤** 넘기게 한다.

---

## 1. 흐름

```
확장 아이콘 클릭
   ↓
[작업창] 열림 ── 이제 닫히지 않는다. 탭을 옮겨도 그대로 떠 있다
   ↓
① [공실열람 페이지 이동]   →  gongsilnews.com/gongsil
   ↓
② [물건 가져오기]          →  펼쳐 놓은 매물 하나 + 하단 주변환경까지
   ↓
③ ChatGPT / Gemini 선택
   ↓
④ [AI 기사 작성]           →  AI 탭이 열리고 프롬프트가 채워진다
   ↓                            (작업창은 그대로)
⑤ [작성하기]               →  전송을 눌러 AI가 글을 쓴다
   ↓
⑥ [초안 보내기]            →  ★ 공실뉴스로 가지 않는다
                               ★ 작업창 안에 기사 미리보기로 뜬다
   ↓
⑦ 작업창에서 다듬는다 (몇 번이고)
     · 제목·부제·본문을 직접 타이핑해 고친다
     · [수정사항 요청하기] → AI에게 다시 시킨다 → 미리보기 갱신
     · [이미지 만들기] / [이미지 바꾸기]
   ↓
⑧ [공실뉴스로 보내기]      →  기사쓰기 폼 자동 입력
                               [기사 등록]은 사람이 누른다
```

### 1-1. 버튼이 셋으로 갈린 이유

④ `AI 기사 작성` / ⑤ `작성하기` / ⑥ `초안 보내기` 는 한 번에 묶을 수도 있다.
묶지 않는다.

| 단계 | 사이에 사람이 끼어들 자리 |
|---|---|
| ④ → ⑤ | 프롬프트가 제대로 들어갔는지 눈으로 본다 |
| ⑤ → ⑥ | 기사가 다 나왔는지 본다. 마음에 안 들면 AI 탭에서 직접 다시 시킨다 |

옛 확장에서 에러가 가장 잦던 곳이 **화면이 준비되기 전에 다음 단계로 넘어가는 지점**이었다.
버튼을 나누면 그 사고가 구조적으로 사라진다.

## 2. 구조가 어떻게 바뀌나

### 2-1. 지금 (확장이 페이지를 돌아다닌다)

```
공실 페이지에 버튼 심기 → 모달 → AI 탭에 버튼 심기 → 폼에 입력
        ↑ 판단이 페이지마다 흩어져 있다
```

### 2-2. 앞으로 (작업창이 주인)

```
        ┌──────────────┐
        │   작업창      │  ← 판단·상태·화면 전부 여기
        │  (panel.js)  │
        └──────┬───────┘
     명령 ↓    ↑ 결과
  ┌─────────┼─────────┬──────────┐
  │         │         │          │
공실 탭    AI 탭    기사쓰기 탭
(매물 내놔) (넣어/읽어) (채워)
        ↑ 페이지들은 시키는 일만 한다
```

콘텐츠 스크립트에서 **버튼과 모달을 걷어낸다.** 그것들은 작업창으로 간다.

| 파일 | 바뀌는 것 |
|---|---|
| `panel.html` `panel.css` `panel.js` | **새로 만든다** — 작업창 |
| `content-gongsil.js` | 버튼·모달 제거. "매물 내놔" 에 답하는 일만 |
| `content-chatgpt.js` `content-gemini.js` | 떠다니는 버튼 제거. "프롬프트 넣어" / "응답 읽어" / "전송 눌러" 세 명령만 |
| `content-admin.js` | 그대로 |
| `background.js` | 작업창 열기, 탭 기억 |
| `shared/*` | 그대로. `prompt.js` 에 수정요청·이미지 프롬프트 추가 |

## 3. 작업창이 항상 떠 있게 하는 법

| # | 안건 | 결정 |
|---|---|---|
| 1 | 방식 | `chrome.sidePanel` |
| 2 | 여는 법 | `setPanelBehavior({ openPanelOnActionClick: true })` — 아이콘을 누르면 열린다 |
| 3 | 탭을 옮기면 | **전역으로 설정한다**(`tabId` 없이). 탭별로 설정하면 옮길 때 닫힌다 |
| 4 | 지금 동작 | 아이콘을 누르면 공실뉴스로 이동한다 → **없앤다** |
| 5 | 창을 옮기면 | 작업창은 창(window)마다 하나다. 새 창을 열면 거기서 다시 눌러야 한다 |

**⚠ 확인해야 할 것** — 작업창은 창 단위라 탭 전환에는 살아남지만, 브라우저 창을 새로
열면 따라오지 않는다. 실제로 써 보고 걸리면 그때 안내 문구를 넣는다.

### 4-1. 두 가지 고치는 길을 다 둔다

| 고치는 법 | 쓸 때 | 어떻게 |
|---|---|---|
| **직접 타이핑** | 오타, 한 단어, 숫자 | 미리보기가 `contenteditable` |
| **AI에게 요청** | 문단을 다시 쓰기, 말투 바꾸기 | 같은 대화에 이어서 요청 → 응답을 다시 읽어 미리보기 갱신 |

오타 하나 고치자고 AI를 부르면 느리다. 반대로 문단을 통째로 다시 쓰는 건 손으로 못 한다.

### 4-2. AI에게 수정 요청은 "같은 대화에 이어서"

새 프롬프트를 처음부터 보내지 않는다. **열려 있는 AI 탭의 같은 대화에 이어 붙인다.**
매물 정보를 다시 설명할 필요가 없고, AI가 앞서 쓴 기사를 기억하고 있다.

```
[수정 요청 프롬프트]
위에서 작성한 기사를 아래 요청대로 고쳐서,
같은 JSON 형식으로 다시 출력해 주십시오.

요청: {사장님이 적은 것}
```

| 2 | 이미지 만들기 | AI 탭에 이미지 생성 요청 → 생성된 그림을 작업창으로 가져온다 |

## 6. 순서

| 단계 | 내용 | 확인하는 법 |
|---|---|---|
| **1** | 작업창 뼈대 — 아이콘 클릭 시 열리고 탭을 옮겨도 안 닫힌다 | 탭 이리저리 옮겨 보기 |
| **2** | ①②— 페이지 이동 + 물건 가져오기, 주변환경 포함 | 매물 정보가 작업창에 다 뜬다 |
| **3** | ③④⑤— AI 선택, 탭 열기, 프롬프트 넣기, 전송 | AI가 기사를 쓴다 |
| **4** | ⑥— 초안 보내기 → 작업창 미리보기 | 기사가 작업창에 뜬다 |
| **5** | ⑧— 공실뉴스로 보내기 | 폼이 채워진다 (여기까지가 텍스트 한 바퀴) |
| **6** | ⑦— 직접 수정 + AI 수정 요청 | 고친 게 미리보기에 반영된다 |
| **7** | ⑦— 이미지 만들기·바꾸기 | 사진이 붙는다 |

**5단계에서 한 바퀴가 돈다.** 거기까지 되면 나머지는 얹는 일이다.

## 7. 이번에도 지키는 원칙

앞 계획서 1장에서 정한 것이다. 바뀌지 않는다.

1. **값이 없으면 지어내지 않는다.** 그 줄을 비우고 빨간 줄로 말한다
2. **셀렉터는 `shared/config.js` 한 곳에만** 둔다
3. **확인하지 않은 성공을 알리지 않는다.** 채웠다고 말하려면 채워졌는지 보고 말한다
4. **마지막 [기사 등록]은 사람이 누른다**
