|---|---|
| 메인 영상 줄 | 클립들 (텍스트 편집 카드 한 장 = 타임라인 조각 하나) |

| 글자·스티커·사진·영상 줄 | 레이어 (어느 클립부터 어디까지, 단어 기준도 있음) |

## 5. A로 할 때 맞출 규칙

1. **메인 줄은 빈틈 없이 붙어 다닌다** (캡컷의 "자석 메인 트랙"). 텍스트 편집에는 빈틈·겹침이 없으므로:
   - 빈틈 → 무음 클립으로 바꿈
   - 겹침 → 화면전환으로 바꿈
2. **타임라인에서 조각 끝을 끌어 자르면** → 텍스트 편집에서는 그 부분 단어가 지워진 것(취소선)으로 보인다. 거꾸로도 같다.
   - 말 중간을 자르면 단어가 반쯤 잘리므로 **가장 가까운 단어 경계에 자동으로 붙게** (기본 켜짐)
3. **글자·스티커를 아무 시각으로 끌어 옮기기** — 지금은 "클립·단어 기준"이므로 **"클립 안 몇 초부터·몇 초 동안"** 값을 하나 더한다. 앞에서 글을 지우면 따라 움직이는 장점은 그대로.
4. **영상 위에 다른 영상 얹기(화면 속 화면)**는 레이어(사진·영상 올리기)로.
5. **키프레임**(시간에 따라 위치·크기·투명도·회전 바꾸기)은 타임라인에서 넣는다. 텍스트 편집에서는 그 레이어에 "◆ 키프레임" 표시만, 미리보기·완성 영상에는 똑같이 나온다.
6. **60세 원칙**: 끌기만으로 되게 하지 않는다. 늘 보이는 단추 **[여기서 자르기] [앞 다듬기] [뒤 다듬기]** 함께.

## 6. 만드는 순서 (A일 때)

1. **보기 전환 + 타임라인 화면** — 줄 그리기(클립 썸네일·소리 파형·레이어·소리 줄), 재생 막대, 확대·축소, 클립·레이어 고르기. 데이터는 그대로 (하루 이상)
2. **타임라인 편집** — 조각 자르기·나누기·다듬기·순서 바꾸기, 레이어 시각 끌기·늘이기, 소리 줄, 자석
3. **키프레임** — 위치·크기·투명도·회전
4. **세세한 것** — 자석 켜고 끄기, 프레임 단위 이동(←→), 캡컷과 같은 단축키, [빈 타임라인으로 시작] 카드

## 8. 만든 것 (2026-10-20)

캡컷 화면 33장 분석(10-19 밤)을 바탕으로. **키프레임이 가장 중요** (사장님).

### 8-1. 타임라인 편집 화면 (`TimelineView.tsx`)
- 위 [텍스트 편집 | 타임라인 편집] 단추로 언제든 바꾼다 (같은 프로젝트, 고친 것이 양쪽에 그대로). 고른 보기는 이 PC 에 기억
- 캡컷처럼: 위 = 미리보기, 아래 = 타임라인, 오른쪽 = 속성 칸. 가운데 경계선을 끌어 위아래 크기
- 줄 (위→아래): 글자·스티커·사진(앞에 보이는 것일수록 위 줄) · 메인자막 · 화면(메인, 썸네일 필름) · 소리(AI 목소리·원본 소리 파형) · 배경 음악 · 효과음
- 메인 줄은 빈틈 없이 붙는다(자석). 클립 몸통 끌기 = 순서 바꾸기, 양 끝 끌기 = 다듬기
  - 원본 영상: 쓰는 구간 (가까운 단어 경계에 붙음) / 사진·영상만 넣은 클립: 길이 / AI 목소리: 끝에 머무는 시간 (목소리보다 짧게는 못 함)
- 글자·스티커·사진·음악·효과음 막대: 몸통 끌기 = 시각 옮기기, 양 끝 = 길이. 클립 끝·다른 막대·재생 막대에 붙는다
  - 저장은 "시작 클립 + 몇 초 뒤 (ts) ~ 끝 클립 + 몇 초 (te)" — 앞 클립 글을 지우면 같이 움직이는 장점 그대로 (5장 3)
- 도구 줄 (60세 원칙 — 늘 보이는 단추): 되돌리기 · **나누기**(Ctrl+B) · 앞 지우기 · 뒤 지우기 · 지우기 · 반전 · 돌리기(90°) · **◆ 키프레임** · 확대·축소(Ctrl+휠) · 맞춤
- ←→ 한 칸(1/30초), Shift+←→ 1초. 화면전환은 클립 사이에 마우스를 올리면 [+]
- 오른쪽 사진·영상을 타임라인 화면 줄에 끌어 놓으면 앞·뒤에 넣기 / 바꾸기, 글자 줄에 놓으면 사진 올리기
- 타임라인에서 [텍스트]·[스티커]를 넣으면 재생 막대 자리부터 3초

### 8-2. 키프레임 (`Keyframes.tsx` KeyframeBox, `timeline.ts` kfAt …)
- 대상: 화면 글자 · 스티커 · 사진 올리기 · **클립 화면(사진·영상)** — 자리·크기·회전·진하기
- 점 = 그 시각의 모습 한 장. 점 사이는 저절로: 일정하게 / 부드럽게 / 천천히 시작 / 천천히 끝
- 점이 하나라도 있으면 미리보기에서 끌어 옮기기·크기·회전을 바꿀 때 지금 시각에 점이 저절로 생긴다 (캡컷과 같다)
- 오른쪽 속성 칸 맨 위: [이 시각에 점 찍기 / 빼기] [◀ 앞 점] [다음 점 ▶], 점 목록(누르면 그 시각으로), 크기·회전·진하기·가로·세로 막대, 움직이는 방식
- **빠른 움직임** 12가지 (점을 알아서 찍음): 점점 커지기·작아지기, 왼/오/위/아래에서 들어오기, 왼/오로 나가기, 돌며 나타나기, 서서히 나타나기·사라지기, 왼→오 흐르기
- 클립 화면에 키프레임이 있으면 사진 자동 움직임(줌인 등)은 쉰다
- 타임라인 막대·텍스트 편집 썸네일에 ◆ 표시
- **키프레임 칸은 타임라인 편집에서만 보인다** (2026-10-20 사장님: 텍스트 편집에서는 복잡하고 헷갈려서 — 기능·찍어 둔 점·완성 영상 움직임은 그대로)

### 8-3. 서로 보완 — 없던 기능

- **필터·색 보정** (캡컷 [필터]·[조정]): 필터 10가지(매물 화사하게·선명하게·밝게·따뜻하게·차갑게·영화처럼·빛바랜·흑백·옛날 사진·어둡게) + 세기, 밝기·대비·채도·색온도·색조. [모든 클립에 똑같이]

- 초 단위로 나오는 구간 (위 8-1)

### 8-4. 완성 영상 (앱 `render.js`) — 미리보기와 같은 계산
- 클립 화면 키프레임: 칸마다 크기 → 큰 투명 판의 "돌리기 전 자리"에 얹기 → 판 가운데로 돌리기 → 자르기 → 진하기(sendcmd) → 바탕(검정·흐린 배경). 영상도 된다
- 글자 키프레임: 자막 엔진 칸마다 (애니메이션과 같은 길) · 스티커·사진 키프레임: 편집 화면이 칸마다 그린 그림(AnimBake)
- 옛 앱으로 내보내면 [내보내기] 창에 "업데이트해 주세요" 알림 (`features`)
- 시험: 사진(작게 돌며 커지기·진하기 30→100%)·글자(대각선 이동·커지기·회전)·영상(15° 돌리기+흐린 배경)·"1~2초만" 구간 — 굽기 결과와 미리보기가 같은 자리·각도

## 9. 회의 (2026-10-20 아침) — 두 화면은 자료만 같이, 생김새·고치는 법은 따로

사장님 결정:
1. **텍스트 편집에서는 키프레임 칸을 안 보인다** — 기능·찍은 점·움직임은 그대로 (복잡하고 헷갈려서). → 반영함
2. **타임라인 편집 속성 칸은 텍스트 편집과 달라야 한다** — 캡컷처럼. 키프레임은 **캡컷 방식 (항목마다 ◇)**: 크기·위치·회전·진하기를 따로 점 찍기
3. **타임라인에서 한 작업을 텍스트 편집이 100% 고칠 수 없어도 괜찮다** — 텍스트 편집은 "보여 주고 지키기"만
   - 단, 텍스트 편집에서 단어를 지우거나 클립을 옮겨도 타임라인 작업이 망가지지 않게 (키프레임·초 단위 구간은 클립에 붙어 따라간다)
4. **타임라인 편집 화면(인터페이스)은 텍스트 편집과 달라도 된다** — 텍스트 편집(브루식)은 전통적인 타임라인 편집이 아니므로, 타임라인 편집은 캡컷 같은 전통 방식으로 따로 짠다 (메뉴·단추·속성 칸)

만들 것 (다음):
- 타임라인 전용 속성 칸 — 탭: 기본 · 애니메이션 · 필터·색 보정 · 텍스트(글자일 때). 기본 탭 = 크기%·위치 X·Y·회전°·진하기% 숫자 칸 + 막대 + 항목마다 ◇ + ↺, 정렬 단추 줄, 나오는 시작·길이(초)
- 키프레임 자료를 항목마다로 바꾸기 (예전 "모든 항목 한 번에" 점은 그대로 읽어서 옮긴다)

### 9-1. 반대쪽 원칙 (사장님): 텍스트 편집에서 한 모든 작업은 타임라인 편집에서 100% 받아야 한다
- 텍스트 편집 → 타임라인: **100%** (그대로 보이고, 이어서 고칠 수 있게)
- 타임라인 → 텍스트 편집: 보여 주고 지키기만 (고칠 칸이 없어도 됨)

이미 되는 것: 지운 단어·무음 줄이기(클립 길이), AI 목소리·빠르기·늘린 길이, 화면·채우기·반전·사진 움직임, 메인자막(따로 고친 글·클립별 서식·애니메이션·예능 자막), 글자·스티커·사진·음악·효과음(단어 구간도 그 시각에), 화면전환

### 13-12. 녹화 → 실제 말소리로 클립 (2026-10-20)
- 예전: 프롬프터 대본을 문장마다 잘라 클립 (실제 말과 어긋남 — 1.3초 녹화가 0.05초 클립 17개).

## 13-13. 새로 만들기 3가지 · 대본 갈래 · 만드는 방식 (2026-10-20 사장님)

- 새로 만들기 = **대본 쓰고 편집하기 / 촬영한 영상으로 편집하기 / 녹음한 음성으로 편집하기** 3가지.
  - 롱폼 → 숏폼은 없앰 (지금 필요 없음). 영상 녹화는 새로 만들기에서 빼고 [강의/영상녹화] 메뉴에서만.
- 대본 쓰고 편집하기 — 대본 갈래 3가지:
  - **매물 소개**: 공실 고르기 · 번호로 찾기(공실번호/경매 관리번호) · [공실열람] 새 창 · 용도(릴스·쇼츠/매물 설명/단지·지역/기타) · 유튜브 대본 가져오기.
  - **뉴스 기사**: 공실뉴스 기사(최근 30건 목록 + 제목 찾기 + 주소 붙여넣기) / 네이버 뉴스(주소 붙여넣기 · 네이버 뉴스 열기 · 지금 보는 뉴스 가져오기 — 뉴스칼럼과 같은 읽기).
    용도 릴스·쇼츠 / 뉴스·칼럼 / 기타. 기사 문장은 옮기지 않고 사실만 살려 새로 쓰며, 마지막 문장에 출처.
  - **자유 주제**: 주제로 AI 쓰기, 또는 대본을 오른쪽 칸에 바로 붙여 넣기.
- 대본을 다 쓰면 **만드는 방식**을 고른다: [직접 녹화·녹음하고 편집] → 대본을 프롬프터에 넣고 녹화 창으로 (녹화가 끝나면 대본이 자막 글) / [AI 보이스로 만들고 편집] → 지금의 영상 꾸미기.
- 남은 것: 녹화 창에 "소리만(마이크만) 녹음" 방식은 아직 없음 — 지금은 화면·카메라 녹화.

## 13-14. 보도자료 · 화면 캡쳐 자동 넣기 (2026-10-20 사장님)

- 기관 화면 본문 읽기 보강: 기관 게시판 본문 칸 → 안쪽 창(정책브리핑 문서 보기, 창 안의 창) → 문단 모음. 뉴스 읽기가 요약만 잡으면 더 긴 본문으로.

  - 공실뉴스 기사·보도자료: 제목(또는 본문 칸)부터 아래로 최대 4장. 보도자료는 오른쪽 아래 "출처: ○○".

  - 매물 소개: 공실 분석 때 찍어 둔 공실열람 검증·지도·로드뷰 3장도 함께.

## 13-15. 기본 파일 이름 (2026-10-20 사장님)

- 기본 파일 이름 = **`년월일6자리 제목.확장자`** (예: `261020 논현동 빌라 연립.gss`). 앞은 늘 년월일. 단 **기본값일 뿐** — 회원이 이름·폴더를 마음대로 고칠 수 있다.
- 제목 기본값: 매물 소개 = 매물 이름 / 뉴스 기사 = 기사 제목(30자) / 자유 주제 = 주제 / 없으면 무제.
- 같은 이름이 있으면 덮어쓰지 않고 `_2`, `_3`.
- 적용: 영상 프로젝트(.gss)·녹음(.wav)·대본(.txt)·완성 영상(.mp4, 비율 꼬리 없이 프로젝트 이름 그대로)·AI 보이스 녹음(`261020 AI 보이스`)·녹화(`261020 화면 녹화`)·캡쳐(`캡쳐\261020 제목\261020 제목_01.jpg`).
- 영상 꾸미기 ⑥ 파일 이름: 프로젝트명 `.gss` · 녹음 파일명 `.wav` 한 줄씩 + [저장 폴더] (누르면 폴더 고르기). 녹음 폴더를 바꾸면 AI 보이스 녹음 기본 폴더도 같이.
- 폴더 정리(맨 위는 기능별 폴더만, 매물·칼럼은 `매물\`·`칼럼\` 안으로)는 아직 정하지 않음.
