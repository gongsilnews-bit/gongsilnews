# 📋 특강 회원 등록·승인과 수수료·월 정산·환불 회의록

**일시:** 2026년 09월 28일 (월)
**참석자:** 사장님, Claude (AI 파트너)
**회의 주제:** 특강관리를 기사관리처럼 모든 회원에게 열고, 최고관리자 승인제로 운영한다.
강의별 수수료를 떼고 월 정산으로 등록자에게 포인트를 지급하며, 등록자는 수입현황을
투명하게 보고 환불도 직접 처리한다.

---

## 0. 결정 요약

| 항목 | 결정 |
|---|---|
| 강의 등록 | **유료회원만** (공실스터디부동산·공실뉴스부동산·비즈니스회원) + 최고관리자(무제한) |
| 등록 한도 | [회원관리 → 등급별 한도 설정]에 **최대 강의 등록** 칸 (기본: 유료 3건, 무료 0건) + 회원별 개별 조정 |
| 공개 | 회원 등록 → **승인대기** → 최고관리자 **승인 시 판매중** |
| 강의 설정 | **최고관리자만** |
| 수수료 | 최고관리자가 **기본 수수료율** 설정 + **강의별로 따로** 조정 |
| 정산 | **월 정산** — 수익은 정산대기로 쌓였다가 관리자가 정산 완료 시 **포인트 지급** |
| 수입현황 | 등록자가 **건별 내역까지** 볼 수 있게 (투명성) |
| 환불 | **등록자가 직접** 처리. 최고관리자는 전체 조회 + 강제 환불 |
| 현금 출금·세금 | **나중에** 설계. 지금은 "수익 포인트" 구분만 미리 해 둔다 |

## 1. 현재 코드 상태 (회의 중 확인)

이미 되어 있는 것:

- `lectures.author_id` (등록자) 컬럼이 있다.
- 상태값에 `PENDING`(승인대기)이 이미 정의되어 있다 — `StudySection.tsx` 의 `STATUS_MAP`.
- 저장 권한이 "관리자 **또는 본인 강의**"로 짜여 있다 — `lecture.ts` 의 `lectureEditor()`.
- 회원 페이지(user_admin, realty_admin)에 [특강관리] 메뉴 자리는 있다 (현재 "준비중" 화면).

바꿔야 하는 것:

- **⚠️ 보안 구멍:** `updateLectureStatus()` 에 권한 확인이 없다. 회원 등록을 열면
  회원이 자기 강의를 스스로 "판매중"으로 바꿀 수 있다. **1단계에서 반드시 막는다.**
- `enrollLecture()` 가 수강료 포인트를 **즉시 100% 등록자에게** 넣는다. 수수료도,
  정산 기록도 없다. 정산·출금 관련 코드는 프로젝트 어디에도 없다.

## 2. 회원 강의 등록과 승인

### 2-1. 화면 권한

| 요소 | 최고관리자 | 회원 |
|---|---|---|
| 목록·검색 | 전체 강의 | **본인 강의만** |
| [+ 새 강의 등록] | ○ | ○ |
| [강의 설정] | ○ | ✕ |
| [수강안내 관리] | ○ | ✕ |
| 무료 등급 지정 | ○ | ✕ (멤버십 정책과 엮여 있음) |
| 수강료 입력 | ○ | ○ |
| 수수료율 | 설정·수정 | **보기만** |
| 승인·반려 | ○ | ✕ |

화면을 두 벌 만들지 않는다. 기존 `StudySection` 을 재사용하고 권한에 따라 버튼만 숨긴다.

### 2-2. 상태 흐름

```
회원 저장 ──▶ 승인대기(PENDING) ──[승인]──▶ 판매중(ACTIVE)
                    │
                    └──[반려 + 사유]──▶ 반려(REJECTED) ──회원 수정 후 재제출──▶ 승인대기
```

- 반려할 때 사유를 입력받고 등록자에게 **알림**을 보낸다 (기사관리 반려와 같은 방식).
- **판매중인 강의를 회원이 수정하면 다시 승인대기로 돌린다.** 가격이나 내용을
  몰래 바꾸는 것을 막기 위해서다.
- 새 강의가 올라오면 최고관리자 사이드바 [특강관리]에 **알림 숫자 뱃지**를 띄운다.

### 2-3. 최고관리자 목록

기사관리처럼 탭과 일괄 버튼을 둔다.

- 탭: `전체 / 승인대기 / 판매중 / 반려 / 종료`
- 버튼: [선택 승인] [선택 반려]
- 칸 추가: **등록자**, **수수료율**(목록에서 바로 수정)

---

## 3. 수수료

- 최고관리자 [강의 설정]에 **기본 수수료율**을 둔다 (예: 30% → 공실뉴스 30%, 등록자 70%).
- 새 강의는 기본값을 물려받고, 최고관리자가 **강의별로 따로** 바꿀 수 있다.
- 회원은 등록 화면에서 **"수수료 30%가 적용됩니다"** 안내를 본다 (분쟁 예방).
- **수강 시점의 수수료율을 판매 기록에 박아 둔다.** 나중에 수수료율을 바꿔도
  지난 판매의 정산 금액은 바뀌지 않는다.

---

## 4. 월 정산

### 4-1. 흐름

```
수강생 결제(포인트 차감)
   ↓
판매 기록 생성: 결제액 / 수수료율 / 수수료 / 등록자 몫 / 상태=정산대기
   ↓ (매월 1일)
최고관리자: 지난달 정산대기 목록 확인 → [정산 완료]
   ↓
등록자에게 "수익 포인트"로 지급 + 판매 기록 상태=지급 완료
```

- 등록자 화면에 **"다음 정산일: 10월 1일"** 을 보여 준다.
- 멤버십 무료 수강(결제 0원)은 판매 기록에 남기되 금액이 0이다.

### 4-2. 수익 포인트 구분 (현금 출금 대비)

현금 출금은 나중에 붙이지만, 지금부터 포인트를 두 종류로 나눠 적립한다.

| 종류 | 출처 | 수강 사용 | 현금 전환 (나중) |
|---|---|---|---|
| 충전 포인트 | 결제 충전, 가입·이벤트 보너스 | ○ | ✕ |
| **수익 포인트** | 강의 정산 지급 | ○ | ○ |

나누지 않으면 충전하자마자 현금으로 빼는 **환전 통로**가 생긴다. 과거 기록을
나중에 다시 가르는 일이 없도록 지금부터 표시해 둔다.

### 4-3. 기존 판매 이관

지금까지 즉시 100% 지급된 판매 건은 판매 기록에 **"지급 완료, 수수료 0%"** 로 옮겨
넣어 수입현황 이력이 끊기지 않게 한다.

---

## 5. 등록자 수입현황 (투명성)

회원 특강관리 안에 **"내 강의 수입현황"** 탭을 둔다.

**① 요약 카드**

| 총 판매 | 공실뉴스 수수료 | 내 수익 | 정산대기 | 지급 완료 | 환불 |
|---|---|---|---|---|---|

**② 강의별 현황**
강의명 / 수강생 수 / 수수료율 / 총 판매 / 내 수익 / 정산대기 / 지급 완료

**③ 판매·환불 내역 (한 건씩)**
날짜 / 강의명 / 수강생(김*수처럼 가림) / 결제 포인트 / 수수료(%) / 내 수익 / 상태
— 환불도 `환불 −10,000P (사유: 개인 사정)` 처럼 한 줄씩 남긴다.

**④ 기간 필터:** 이번 달 / 지난달 / 직접 선택

투명성은 합계가 아니라 **③ 건별 내역**에서 나온다.

최고관리자는 같은 화면을 **전체 등록자 기준**으로 보고, 등록자를 누르면 그 사람이
보는 화면이 그대로 보인다. **같은 데이터를 양쪽이 보므로 숫자가 어긋나지 않는다.**

---

## 6. 환불

### 6-1. 흐름

```
수강생: [환불 요청] (사유 입력) ──알림──▶ 등록자
등록자: 환불 요청 목록 → [승인] 또는 [거절 + 사유]
승인 시: 수강생에게 포인트 반환 + 수강 권한 즉시 종료
```

- 등록자는 요청 없이 **직접 환불**할 수도 있다 (전화 요청 등).
- 최고관리자는 모든 환불을 보고, 분쟁 시 **강제 환불**할 수 있다.

### 6-2. 정산 시점과의 관계

| 환불 시점 | 처리 |
|---|---|
| **정산 전** (정산대기) | 해당 판매 건을 취소 처리. 등록자 몫이 아직 안 나갔으므로 회수 없음 |
| **정산 후** (지급 완료) | 수강생에게 먼저 반환 → 등록자 **포인트 잔액에서 즉시 차감** |

- 잔액이 모자라면 **마이너스로 두고 다음 수익에서 자동으로 메운다.**
- 월 정산을 택한 이유가 이것이다. 대부분의 환불은 정산 전에 일어나 회수할 일이 드물다.

### 6-3. 세부 규칙

1. **공실뉴스 수수료도 함께 돌려준다.** 수강생은 낸 금액 전부를 받는다.
2. **부분 환불 허용.** 등록자가 금액을 입력하고, 수수료는 비율대로 줄인다.
3. **수강생 요청 가능 기간**을 둔다 (기본 7일, 최고관리자가 [강의 설정]에서 변경).
   기간이 지나면 등록자 재량의 직접 환불만 가능하다.
4. 멤버십 무료 수강은 환불 대상이 아니다 (수강 취소만).

## 7. 작업 단계

| 단계 | 내용 |
|---|---|
| **1단계** | 회원 강의 등록 + 승인대기/승인/반려 + 알림 뱃지 + `updateLectureStatus` 권한 막기 |
| **2단계** | 기본·강의별 수수료 + 판매 기록 테이블 + 월 정산(정산대기 → 지급 완료) + 수익 포인트 구분 + 기존 판매 이관 |
| **3단계** | 등록자 수입현황 탭 + 최고관리자 등록자별·강의별 정산 화면 |
| **4단계** | 환불 요청·처리 + 정산 후 차감(마이너스 잔액) |
| 나중 | 수익 포인트 현금 전환 + 출금 + 원천징수 (세율은 세무사 확인 후 설정값으로) |

앞 단계가 끝나야 다음 단계를 검증할 수 있으므로 순서대로 진행한다.

## 8. 메뉴 구성

한 화면에 승인·정산·환불·설정을 다 넣지 않는다. 최고관리자 [회원관리]처럼
마우스를 올리면 펼쳐지는 **하위 메뉴**로 나눈다.

### 8-1. 최고관리자 [특강관리]

| 하위 메뉴 | 내용 |
|---|---|
| **강의목록** | 전체 / 승인대기 / 판매중 / 반려 / 종료 탭, [선택 승인]·[선택 반려], 등록자·수수료율 칸 |
| **정산관리** | 월 정산 실행, 등록자별·강의별 합계, 등록자 클릭 시 그 사람의 수입현황 |
| **환불관리** | 전체 환불 내역, 분쟁 시 강제 환불 |
| **강의설정** | 기본 수수료율, 환불 요청 가능 기간, 기존 강의 설정 항목, 수강안내 관리 |

지금 팝업인 [강의 설정]·[수강안내 관리]는 **[강의설정] 페이지 안으로 옮긴다.**
강의목록에는 [+ 새 강의 등록] 버튼만 남는다.

### 8-2. 회원 [특강관리] (user_admin, realty_admin)

| 하위 메뉴 | 내용 |
|---|---|
| **내 강의** | 본인 강의 목록·상태(반려 사유 포함), [+ 새 강의 등록] |
| **수입현황** | 요약 카드, 강의별 현황, 건별 판매·환불 내역, 다음 정산일 |
| **환불요청** | 수강생 요청 목록, [승인]·[거절], 직접 환불 |

최고관리자 페이지는 하위 메뉴 기능이 이미 있다. 회원 페이지 두 곳은 없으므로 1단계에서 붙인다.

## 9. 코드 구조 원칙

**하위 메뉴 1개 = 화면 파일 1개, 기능 1개 = 서버 파일 1개.**
독립 파일(컴포넌트)로 만들어 관리자·회원이 **같이 쓰고**, 필요할 때만 불러온다.

### 9-1. 화면 (`components/admin/study/`)

```
StudyListSection.tsx       강의목록·내 강의 (관리자·회원 공용, 권한으로 버튼만 다르게)
SettlementSection.tsx      정산관리 (관리자)
EarningsSection.tsx        수입현황 (회원 + 관리자 정산 상세에서 재사용)
RefundSection.tsx          환불관리·환불요청 (관리자·회원 공용)
StudySettingsSection.tsx   강의설정 (기존 팝업을 페이지로)
```

### 9-2. 서버 함수 (`app/actions/`)

```
lecture.ts            강의 저장·조회·수강 (기존, 포인트 지급 로직은 정산 쪽으로 옮김)
lectureApproval.ts    승인·반려 + 최고관리자 권한 확인 (보안 구멍 막는 곳)
lectureSettlement.ts  판매 기록·월 정산·수입현황 조회
lectureRefund.ts      환불 요청·처리·정산 후 차감
```

### 9-3. 원칙

- **파일 하나는 400줄 안팎.** 넘어가면 쪼갠다.
- **관리자용·회원용을 따로 만들지 않는다.** 같은 파일을 쓰고 권한으로 보이는 것만 다르게 한다.
- **돈이 오가는 계산(수수료·정산·환불)은 서버 파일 한 곳에만** 둔다. 흩어지면 숫자가 어긋난다.
- **무거운 화면은 누를 때 불러온다.** 강의 작성폼(`StudyWriteForm`, 1,178줄)은 지금 목록을
  열 때 함께 불러오므로, [+ 새 강의 등록]·[수정]을 누를 때 불러오도록 바꾼다.
- **강의 작성폼은 이미 독립 파일**이다. 회원 페이지에서도 그대로 불러 쓰고,
  무료 등급 숨기기·수수료 안내 추가 같은 **작은 수정만** 한다. 파일을 쪼개는 공사는 하지 않는다.
- **기사관리는 이번 작업과 무관하다.** 건드리지 않는다.

## 10. 나중에 정할 것 (현금 출금 설계 때)

- 출금에 필요한 등록자 정보: 실명, 계좌, 주민번호 또는 사업자번호 (암호화 저장)
