# 유리창 홍보지 — 물건 종류별 표시 항목

> 작성 2026-10-01 · 대상: 공실관리 [유리창홍보지] (`marketing/ai-detail`)
> 원칙: 압구정 유리창 연구 결과 — **가격 > 물건명·크기 > 전화번호** 순서로 크게, 나머지는 물건 종류에 맞는 것만 짧게.

---

## 1. 공통 틀 (모든 물건)

A4 한 장, 세로/가로 선택. 위에서부터:

| 자리 | 내용 | 비고 |
|---|---|---|
| ① 머리 | [딱지] [거래구분] | 딱지: 급매·초급매·신규·가격조정 |
| ② 물건명 | 아주 크게 | 길면 한 줄에 맞게 자동 축소 |
| ③ **크기 줄** | 물건 종류마다 다름 (아래 표) | 예: `46평 · 25층` / `전용 30평 · 3층` |
| ④ **금액** | 가장 크게 (종이 높이 13%) | 물건 종류마다 표시 방식 다름 (아래) |
| ⑤ 사진 | 켜기/끄기 | 아파트는 기본 끄기 권장 |
| ⑥ **정보 표** | 물건 종류마다 다름 (아래 표) | 4~6줄 |
| ⑦ 특징 | 옵션 + 특징 설명 | 칸에 맞게 글자 자동 축소 |
| ⑧ 연락처 띠 | 사무소명 · 대표/등록번호 · 전화 크게 · QR | QR → 매물 상세보기 |

- 모든 항목은 입력란의 **[표시]** 체크로 넣고 뺄 수 있다 (물건명·금액·사무소명·전화는 항상 표시).
- 금액(거래구분·보증금·월세·관리비)은 열 때마다 **공실관리 최신 값**으로 채운다.
- 등록되지 않은 값(`-층`, `-개`)은 자동으로 숨긴다.

## 2. 물건 종류 (공실 등록 기준)

| 1차 분류 | 2차 분류 |
|---|---|
| 아파트·오피스텔 | 아파트, 아파트분양권, 오피스텔, 오피스텔분양권 |
| 빌라·주택 | 빌라/연립, 단독/다가구, 전원주택, 상가주택 |

| 상가·사무실·건물·공장·토지 | 상가, 사무실, 건물/빌딩, 공장/창고, 지식산업센터, 토지 |
| 분양 | 아파트, 오피스텔, 빌라, 도시형생활주택, 생활숙박시설, 상가/업무 |

## 3. 묶음별 표시 항목

### A. 아파트 · 오피스텔 (분양권 포함)
손님은 **단지명 + 평형**으로 찾는다. 사진보다 숫자.

| 자리 | 항목 | 등록 데이터 |
|---|---|---|
| 크기 줄 | **공급 평형** · 해당층 | `supply_py`, `current_floor` |
| 금액 | 매매가 / 전세금 / 보증금·월세 | `deposit`, `monthly_rent` |
| 정보 표 | 공급/전용 면적 | `supply_m2`, `exclusive_m2` |
| | 방/욕실 · 방향 | `room_count`, `bath_count`, `direction` |
| | 동 (선택) | `apt_dong` |
| | 관리비 · 입주가능일 | `maintenance_fee`, `move_in_date` |
| | **단지 정보: 세대수 · 준공연도** | `metadata.approval_year` (세대수는 **현재 미등록** ※) |
| | **커뮤니티** (헬스·수영장 등) | **현재 미등록** ※ |
| 특징 | 옵션 (시스템에어컨·빌트인 등) · 특징 설명 | `options`, `description` |
| 사진 | 기본 **끄기** | |

> ※ 세대수·커뮤니티는 공실 등록 항목에 없다. → **결정 필요** (5장 참고)

### B. 빌라 · 연립 / 원룸 · 투룸
실평수와 **방 개수·옵션**이 핵심. 엘리베이터·주차 여부가 큰 차이.

| 자리 | 항목 | 등록 데이터 |
|---|---|---|
| 크기 줄 | **전용 평형** · 방 개수 · 해당층 | `exclusive_py`, `room_count`, `current_floor` |
| 금액 | 보증금·월세 / 전세 / 매매 | |
| 정보 표 | 방/욕실 · 방향 | |
| | 엘리베이터 · 주차 | `options`(엘리베이터), `parking` |
| | 관리비 (포함 항목) · 입주가능일 | |
| | 준공연도 | `metadata.approval_year` |
| 특징 | **옵션 아이콘 위주** (세탁기·냉장고·에어컨…) · 특징 설명 | |
| 사진 | 기본 **켜기** (내부 사진) | |

### C. 단독 · 다가구 · 전원주택 · 상가주택
건물 전체를 파는 경우가 많다 → **대지·연면적·층수·수익**.

| 자리 | 항목 | 등록 데이터 |
|---|---|---|
| 크기 줄 | **대지 평수** · 지상/지하 층수 | `land_share_py`, `ground_floors`, `underground_floors` |
| 금액 | 매매가 (임대면 보증금·월세) | |
| 정보 표 | 대지면적 · 연면적 | `land_share_m2`, `supply_m2` |
| | 용도지역 · 도로 폭 | `zoning`, `road_width` |
| | 준공연도 · 구조 | `approval_year`, `building_structure` |
| | 주차 | `parking` |
| | **현 임대 현황** (보증금/월세 합계) | `current_rental_deposit`, `current_rental_monthly` |
| 특징 | 마당·옥상·차고 등 옵션 · 특징 설명 | |
| 사진 | 기본 **켜기** (외관) | |

**전용면적·층·주차·입주 시기**. 지식산업센터는 층고·드라이브인.

| 자리 | 항목 | 등록 데이터 |

### F. 건물 · 빌딩 / 공장 · 창고
투자·사업용. **대지·연면적·층수·수익률 / 층고·전력**.

| 자리 | 항목 | 등록 데이터 |

## 4. 금액 표시 규칙

| 거래 | 표시 | 예 |
|---|---|---|
| 매매 | `매매가` + 금액 | 매매 **49억** |
| 전세 | `전세금` + 금액 | 전세 **15억** |
| 월세 · 단기 | `보증금 / 월세` | **2억 / 520만** |
| 상가 월세 | 위 + 권리금 줄 | **5천 / 300만** · 권리금 1억 |
| 토지 매매 | 금액 + 평당가 | **12억** (평당 800만) |

## 5. 결정이 필요한 것

1. **아파트 세대수·커뮤니티** — 공실 등록 항목에 없다.
   - (가) 공실 등록에 칸 추가 (세대수, 커뮤니티 체크) — 확실하지만 등록이 길어짐
   - (나) 홍보지 입력란에서만 직접 적기 — 빠름, 매물마다 새로 적어야 함
   - (다) 단지명으로 공동주택 단지 정보(공공데이터)를 자동 조회 — 가장 편하지만 개발 필요
   - **권고: 우선 (나)로 시작하고, 쓰임이 많으면 (다)**
2. **분양** 매물 — 분양가·입주 예정일 중심의 별도 틀이 필요한지
3. 묶음별 **기본 사진 켜기/끄기** 값이 위 표대로 괜찮은지

## 6. 구현 순서 (제안)

1. 공실 데이터에서 `property_type`·`sub_category`·`metadata` 를 홍보지로 가져오기 (`loadVacancyDataDirectly`)
2. 묶음(A~G) 판별 → 크기 줄·정보 표 항목을 묶음별로 자동 구성
3. 입력란도 묶음에 맞는 칸만 보이게 + 각 칸 [표시] 체크 유지
4. 1번 디자인 먼저 → 2~5번 디자인에 같은 규칙 적용
