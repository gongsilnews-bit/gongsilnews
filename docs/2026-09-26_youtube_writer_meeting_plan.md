## 0. 한 줄 목표

기존 기사 초안을 참고하여 **유튜브 대본, 장면별 이미지, 썸네일**을 한곳에서 만들고,
대본 길이와 선택한 장면 길이에 맞춰 장면 수를 자동 결정한 뒤 각 이미지를 정확한 장면에
자동 배치하는 `4 · 유튜브 작성` 탭을 추가한다.

## 1. 이번 회의에서 합의한 내용

| 항목 | 결정 |
|---|---|
| 새 메뉴 | `3 · 블로그 작성` 옆에 `4 · 유튜브 작성` 추가 |
| 참고 원본 | `2 · 초안 다듬기`에서 완성한 기사 |
| 기존 데이터 보호 | 유튜브 결과는 기사·블로그와 별도 상태로 저장하고 원문을 변경하지 않음 |
| 핵심 결과물 | ① 유튜브 대본 ② 장면별 이미지 ③ 유튜브 썸네일 |
| 영상 종류 | 쇼츠 `9:16`과 일반 유튜브 `16:9` 지원 방향 |
| 장면 구성 | 사용자가 `짧게 / 중간 / 길게`를 선택하면 AI가 그 간격으로 대본을 나누고 각 장면에 고유 ID 부여 |
| 이미지 수 | 개수를 미리 고정하지 않고 대본 재생시간과 장면 길이에 맞춰 자동 결정 |
| 다량 이미지 | 생성된 모든 이미지를 고유 장면 ID를 기준으로 자동 매칭 |
| 이미지 생성처 | ChatGPT·Gemini 연동을 지원하고, 향후 직접 이미지 API도 선택 가능하게 설계 |
| 이미지 스타일 | 한국형 스타일 7종 제공 |
| 대표 스타일 | `프리미엄 PPT 프레젠테이션` 포함 |
| 통일성 | 영상 전체에 색감·글꼴·카메라 분위기·비율을 고정하는 `스타일 잠금` 제공 |
| 한글 처리 | AI 이미지에 한글을 그리게 하지 않고 작성기가 정확한 한글을 별도 합성 |

## 2. 전체 사용자 흐름

```text
1 · 매물·AI
   ↓
2 · 초안 다듬기에서 기사 확정
   ↓
4 · 유튜브 작성
   ↓
① 영상 설정
   · 매물 소개 / 부동산 뉴스 / 지역 분석
   · 60초 쇼츠 / 약 2분 / 약 5분
   · 장면 길이: 짧게 / 중간 / 길게
   · 말투, 화면 비율, 이미지 스타일 선택
   ↓
② 유튜브 대본 생성
   · 훅 → 본문 → 요약 → 문의·구독 유도
   · 장면별 내레이션·화면·자막으로 분리
   ↓
③ 장면 이미지 생성
   · 실제 기사·매물 사진 우선
   · 부족한 장면만 AI 생성
   · 대본에서 만들어진 장면 수만큼 이미지 자동 배치
   ↓
④ 썸네일 생성
   · 문구 추천 → 이미지 생성 → 최종 시안 선택
   ↓
⑤ 결과 내보내기
   · 대본 복사
   · 장면 이미지 다운로드
   · 썸네일 다운로드
   · 전체 작업 저장
```

> `3 · 블로그 작성`을 반드시 거치지는 않는다. `2 · 초안 다듬기`의 기사가 준비되면
> 블로그와 유튜브를 서로 독립적으로 만들 수 있게 한다.

## 3. `4 · 유튜브 작성` 화면 구성안

사이드패널 폭이 좁으므로 모든 기능을 한 번에 펼치지 않고, 위에서 아래로 진행하는
세로형 작업 흐름과 접기·펼치기를 사용한다.

┌ 공실뉴스 AI 기사작성기 ─────────────────────┐

│ ┌ 논현동 단독·다가구 매매 50억... ───────┐ │
│ └─────────────────────────────────────────┘ │
│                                             │
│ 1. 영상 설정                                │
│ [매물 소개] [뉴스] [지역 분석]              │
│ [60초 쇼츠] [2분] [5분]                     │
│ 장면 길이 [짧게] [중간] [길게]              │
│ [9:16] [16:9]                               │
│ [뉴스형] [친근한 설명형] [전문가 분석형]    │
│                                             │
│ 2. 이미지 스타일                            │
│ [한국형 보도 실사] [부동산 시네마틱] ...   │
│ [프리미엄 PPT 프레젠테이션]                 │
│ ☑ 스타일 잠금                               │
│                                             │
│ [AI 유튜브 대본 작성]                       │
│ [완성 대본 가져오기]                        │

│ 3. 장면 목록                                 │
│ ┌ 장면 01 · 오프닝 ──────────────────────┐ │

│ └─────────────────────────────────────────┘ │

│ │ ...                                     │ │

### 탭 폭 대응

상단에 네 개의 탭을 한 줄로 넣으면 글자가 좁아질 수 있다. 구현 시 아래 두 안을 실제 폭에서
비교한다.

- 안 A: `[1 매물·AI] [2 초안] [3 블로그] [4 유튜브]` 한 줄
- 안 B: 번호는 유지하고 작은 글자로 두 줄 배치

기본 방향은 기존 흐름이 한눈에 보이는 **안 A**이다.

## 4. 영상 설정

### 4-1. 콘텐츠 유형

| 유형 | 용도 | 기본 구성 |
|---|---|---|
| 매물 소개 | 특정 매물 홍보 | 훅 → 위치 → 핵심 조건 → 장점 → 문의 |
| 부동산 뉴스 | 기사 브리핑 | 헤드라인 → 배경 → 핵심 사실 → 의미 → 전망 |
| 지역 분석 | 동네·상권·입지 설명 | 지역 소개 → 교통 → 생활권 → 시세 → 결론 |

### 4-2. 영상 길이

| 길이 | 기본 비율 | 용도 |
|---|---:|---|
| 60초 쇼츠 | `9:16` | 빠른 매물 소개, 핵심 뉴스 |
| 약 2분 | `16:9` | 뉴스 브리핑, 상세 매물 소개 |
| 약 5분 | `16:9` | 심층 분석, 프레젠테이션형 영상 |

영상 길이는 전체 대본의 재생시간을 결정하며 장면 수를 직접 고정하지 않는다.

### 4-3. 장면 길이

| 선택 | 한 장면의 목표 길이 | 결과 |
|---|---:|---|
| 짧게 | 약 3~5초 | 화면이 자주 바뀌며 장면과 이미지가 많아짐 |
| 중간 | 약 6~9초 | 정보 전달과 화면 변화가 균형을 이룸 |
| 길게 | 약 10~15초 | 한 이미지를 오래 보여주며 장면과 이미지가 적어짐 |

이미지 수는 `영상의 예상 재생시간 ÷ 장면의 목표 길이`를 기초로 계산하되, AI가 문장과
내용이 자연스럽게 끝나는 지점에서 장면을 나눈다. 따라서 같은 2분 대본이라도 `짧게`를
선택하면 이미지가 많아지고 `길게`를 선택하면 적어진다. 특정 숫자로 고정하거나 일률적인
상한을 두지 않는다. 설정을 선택하면 예상 장면·이미지 수를 먼저 보여주고, 대본이 완성되면
실제 장면 수로 갱신한다. 생성 후에는 사용자가 장면을 추가·삭제·합치기·나누기·정렬할 수 있다.

### 4-4. 말투

- 뉴스 앵커형
- 친근한 설명형
- 부동산 전문가 분석형

기본값은 콘텐츠 유형에 따라 자동 추천하되 사용자가 변경할 수 있게 한다.

## 5. 대본의 장면 데이터 규격

대본을 단순한 긴 글로 저장하지 않고 장면 배열로 저장해야 이미지 자동 배치가 가능하다.

```json
{
  "videoTitle": "논현동 50억 단독주택 핵심 분석",
  "videoType": "listing",
  "duration": "2m",
  "sceneLength": "medium",
  "aspectRatio": "16:9",
  "tone": "news",
  "styleId": "korean-news-photo",
  "styleLocked": true,
  "scenes": [
    {
      "sceneId": "scene-001",
      "order": 1,
      "heading": "오프닝",
      "narration": "서울 강남구 논현동에 50억 원대 단독주택이 나왔습니다.",
      "caption": "논현동 단독주택 · 매매가 50억",
      "visualType": "building-exterior",
      "visualPrompt": "서울 논현동의 고급 단독주택 외관...",
      "mediaSource": "generated",
      "mediaId": null,
      "status": "waiting"
    }
  ]
}
```

### 장면 ID 원칙

- 화면에 보이는 순서와 별개로 `sceneId`는 한 번 생성하면 바꾸지 않는다.
- 장면 순서를 옮겨도 이미지 연결은 유지한다.
- 이미지는 생성 요청 시 반드시 해당 `sceneId`와 함께 작업으로 등록한다.
- 이미지가 생성된 순서가 뒤섞여도 완료 응답의 `sceneId`를 보고 정확한 칸에 넣는다.

## 6. 이미지 스타일 7종

### 스타일과 장면 종류는 분리한다

- **스타일:** 영상 전체의 색감과 표현 방식
- **장면 종류:** 건물 전경, 실내, 거리, 지도, 통계 등 화면에 담을 대상

예를 들어 `한국형 보도 실사` 스타일을 선택한 채 건물 전경과 거리 상권을 모두 만들 수 있다.

| # | 스타일 | 설명 | 추천 콘텐츠 |
|---:|---|---|---|
| 1 | 한국형 보도 실사 | 국내 뉴스 현장 사진처럼 자연스럽고 과장되지 않은 실사 | 부동산 뉴스, 정책, 일반 매물 |
| 2 | 부동산 시네마틱 | 고급스럽고 선명한 영화형 색감 | 고가 주택, 빌딩, 프리미엄 매물 |
| 3 | 현장 취재 다큐 | 기자가 현장을 직접 촬영한 듯한 사실적 분위기 | 재개발, 공실, 상권 변화 |
| 4 | 밝은 매물 홍보 | 밝은 채광과 깔끔한 광고 사진 분위기 | 주거·상가 매물 소개 |
| 5 | 한국형 인포그래픽 | 가격·면적·교통·수익률을 방송 그래픽처럼 표현 | 데이터와 숫자 설명 |
| 6 | 한국형 일러스트·웹툰 | 설명을 쉽고 친근하게 전달 | 쇼츠, 개념 설명, 사례 재현 |
| 7 | 프리미엄 PPT 프레젠테이션 | 사진·제목·수치·지도·도표를 세련된 슬라이드로 구성 | 심층 분석, 2~5분 영상 |

### 장면 종류

- 아파트·빌딩·단독주택·상가 외관
- 주거·상업 공간 내부
- 한국 거리·골목·상권
- 역세권·교통
- 지도·입지
- 가격·면적·수익률 통계
- 정책·계약·대출 설명
- 한국인 생활 장면
- 오프닝·요약·문의 화면
- 썸네일 전용 장면

### 스타일 잠금

장면 수가 많아져도 분위기가 제각각이 되지 않도록 아래 항목을 영상 단위로 고정한다.

- 색상 팔레트
- 촬영 시간대와 날씨
- 카메라 렌즈와 구도 성향
- 사실성 정도
- 글꼴과 도표 디자인
- 등장인물 표현 기준
- 화면 비율과 자막 안전 영역

장면별 변경은 허용하되, 변경된 장면에는 `개별 스타일` 표시를 붙인다.

## 7. 한국형 이미지 공통 규칙

모든 이미지 스타일에 다음 규칙을 공통 적용한다.

1. 한국의 아파트·빌라·단독주택·상가 구조를 반영한다.
2. 한국 도로, 차선, 보도블록, 전신주, 골목과 상권 형태를 반영한다.
3. 인물이 필요할 때는 장면의 맥락에 맞는 한국인 성인을 사용한다.
4. 가격은 원화, 면적은 `㎡`와 `평`을 정확하게 사용한다.
5. 미국식 교외주택, 일본식 거리, 중국식 간판 등 외국 요소가 섞이지 않게 한다.
6. 가짜 한글 간판과 읽을 수 없는 글자를 최소화한다.
7. 지역 정보가 있으면 서울·부산·제주 등 실제 지역의 건축·거리 분위기를 반영한다.
8. 실제 매물을 묘사하는 경우 원본과 다른 구조를 사실처럼 단정하지 않는다.
9. AI로 만든 매물 유사 이미지에는 필요 시 `AI 생성 이미지`를 표시한다.

### 한글과 숫자 처리

AI 이미지 모델이 슬라이드 전체를 그리게 하지 않는다.

```text
AI 이미지: 배경, 건물, 인물, 질감
작성기 렌더러: 정확한 한글, 가격, 면적, 그래프, 로고
최종 결과: 두 레이어를 합성한 이미지
```

이 방식으로 `50억`, `231.4㎡`, `논현동` 같은 핵심 정보의 오탈자를 방지한다.

## 8. 실제 사진과 AI 이미지의 우선순위

유튜브 장면도 실제 자료를 우선한다.

1. 관리자가 특정 사진 또는 표현을 지정한 경우 그 요청을 우선한다.
2. 기사·매물에 연결된 실제 현장 사진을 먼저 사용한다.
3. 사용할 수 있는 실제 영상 또는 영상 캡처가 있으면 해당 장면에 사용한다.
4. 자료가 부족한 장면만 한국형 AI 이미지를 생성한다.
5. AI 생성도 실패한 경우 사용자가 직접 업로드할 수 있게 한다.

실제 사진을 사용한 장면과 AI 생성 장면은 내부 데이터에서 출처를 구분한다.

## 9. ChatGPT·Gemini 이미지 가져오기와 장면별 자동 배치

### 핵심 원리

이미지를 단순히 생성 순서로 배치하지 않고, 모든 생성 작업을 장면 ID와 묶는다.

```text
scene-007에서 [이미지 만들기]
   ↓
작업 생성: job-abc123 / sceneId: scene-007
   ↓
ChatGPT 또는 Gemini에서 이미지 생성
   ↓
이미지 결과 수집
   ↓
job-abc123 확인
   ↓
scene-007의 이미지 칸에 자동 삽입
```

따라서 여러 작업의 완료 순서가 `7 → 2 → 15 → 1`처럼 뒤섞여도 서로 바뀌지 않는다.

### 가져오기 방식 3단계

| 방식 | 설명 | 장점 | 주의점 |
|---|---|---|---|
| 직접 업로드 | 내려받은 이미지를 여러 장 선택해 장면 순서대로 배치 | 단순하고 안전 | 사용자가 다운로드·업로드해야 함 |
| 브라우저 연동 | ChatGPT·Gemini 화면의 생성 이미지를 확장이 읽어 장면에 연결 | 현재 사용 흐름과 자연스럽게 연결 | 서비스 화면 구조 변경 시 보완 필요 |
| 직접 이미지 API | 작성기에서 장면별 요청을 보내고 결과를 바로 저장 | 이미지 수가 많을 때 자동화와 재시도에 가장 안정적 | API 키·비용·호출 제한 정책 필요 |

### 권장 운영 구조

- 1차 구현: ChatGPT·Gemini에서 **한 장면씩 만들기·가져오기**와 직접 업로드
- 2차 구현: `전체 장면 이미지 만들기`로 5장씩 순차 처리
- 최종형: 직접 이미지 API를 기본 경로로 사용하고 ChatGPT·Gemini 가져오기를 보조 경로로 유지

직접 API 도입 여부는 구현 전 별도 결정한다. API가 없어도 장면 ID 구조는 처음부터 동일하게 사용한다.

### 다량 이미지 처리 규칙

- 이미지 총개수는 대본 재생시간과 `짧게 / 중간 / 길게` 설정으로 결정한다.
- 생성된 이미지를 한꺼번에 모두 요청하지 않고 기본 5장 단위로 처리한다.
- 각 장면 상태를 `대기 / 생성 중 / 완료 / 실패 / 재생성 필요`로 표시한다.
- 실패한 장면만 다시 요청할 수 있게 한다.
- 사용자가 중지하면 완료된 장면은 유지하고 대기 작업만 멈춘다.
- 같은 장면을 재생성해도 이전 이미지는 즉시 삭제하지 않고 후보로 보존한다.
- 전체 진행률을 `18 / 전체 장면 수 완료`처럼 표시한다.
- 이미지 수와 장면 수가 다르면 자동 확정하지 않고 누락·중복 장면을 표시한다.

## 10. 프리미엄 PPT 프레젠테이션 스타일

PPT 스타일은 AI 사진 한 장이 아니라 **사진과 정보 레이어를 조합한 슬라이드**이다.

### 세부 테마

| 테마 | 디자인 방향 |
|---|---|
| 공실뉴스 브랜드형 | 공실뉴스 파란색 중심, 뉴스와 매물 모두 사용 가능한 기본 테마 |
| 뉴스 브리핑형 | 방송 경제뉴스처럼 제목과 핵심 수치를 빠르게 전달 |
| 프리미엄 부동산형 | 검정·금색·오프화이트 중심의 고급 매물 테마 |
| 데이터 리포트형 | 지도·그래프·가격 비교가 중심인 분석 테마 |

기본값은 `공실뉴스 브랜드형`으로 제안한다.

### 필요한 슬라이드 레이아웃

- 표지
- 핵심 요약 3개
- 큰 사진 + 짧은 설명
- 사진 2분할 비교
- 핵심 숫자 강조
- 지도·교통·생활권
- 가격·면적·수익률 차트
- 장점과 주의점 비교
- 단계·절차 설명
- 결론과 문의 안내

### 출력 비율

- 일반 유튜브: `1920 × 1080` (`16:9`)
- 유튜브 쇼츠: `1080 × 1920` (`9:16`)
- 향후 실제 PPT 파일 출력: `16:9`

가로 슬라이드를 세로로 단순히 자르지 않는다. 같은 데이터를 사용하되 비율별 레이아웃을 따로 렌더링한다.

## 12. 저장 구조와 복원

### 분리 원칙

| 상태 | 저장 내용 |
|---|---|
| 기사 상태 | 기존 제목·부제·본문·대표 이미지 |
| 블로그 상태 | 블로그 전용 제목·본문·이미지·디자인 |
| 유튜브 상태 | 영상 설정·대본·장면·이미지·썸네일 |

유튜브 내용을 수정해도 기사와 블로그는 변하지 않는다.

### 저장소 제안

- `chrome.storage.local`: 영상 설정, 대본, 장면 메타데이터, 작업 상태
- `IndexedDB`: 대본 길이에 따라 생성된 이미지 원본·썸네일·후보 이미지
- 이미지에는 `mediaId`, `sceneId`, 생성처, 생성 시각, 실제/AI 여부를 기록

다량 이미지를 Base64 문자열로 `chrome.storage.local`에만 저장하면 용량과 속도 문제가 생길 수 있으므로 피한다.

### 복원 기준

- 사이드패널을 닫았다 열어도 작성 중인 영상이 복원된다.
- 브라우저가 다시 시작되어도 마지막 저장 작업을 복원할 수 있다.
- 참고 기사 제목이 바뀌었거나 다른 기사를 불러오면 기존 유튜브 작업을 덮어쓰지 않고 새 작업 여부를 확인한다.

## 14. 구현 단계표

- 영상 종류·길이·장면 길이·비율·말투·스타일 설정

- 유튜브 대본 프롬프트
- JSON 응답 검증

- 장면 추가·삭제·합치기·나누기·순서 변경

**완료 기준:** 같은 대본도 장면 길이 선택에 따라 서로 다른 수의 장면으로 자연스럽게 나뉘고 수정 후 복원된다.

### 3단계 — 한 장면 이미지 흐름

- 장면별 이미지 프롬프트 생성
- ChatGPT·Gemini 이미지 요청
- 결과 가져오기
- 직접 업로드·교체·재생성
- 실제 사진과 AI 이미지 출처 표시

**완료 기준:** 장면 하나에서 만든 이미지가 다른 장면으로 들어가지 않는다.

### 4단계 — 가변 장면 수 일괄 처리

- 장면 ID와 이미지 작업 ID 연결
- 5장 단위 순차 처리
- 진행률·중지·재시도
- 실패한 이미지만 재생성
- 긴 대본에서 생성되는 다량 이미지 저장·복원 성능 확인

**완료 기준:** 장면 수와 관계없이 완료 순서가 뒤섞여도 모든 이미지가 각 장면에 정확히 배치된다.

### 5단계 — PPT 프레젠테이션

- 공실뉴스 브랜드형 레이아웃
- 사진과 한글·숫자 레이어 분리
- 지도·수치·비교·요약 슬라이드
- `16:9`와 `9:16` 별도 레이아웃

**완료 기준:** 한글과 숫자가 깨지지 않고, 생성된 모든 장면의 디자인이 통일된다.

### 6단계 — 썸네일과 내보내기

- 썸네일 문구 추천
- 썸네일 시안 생성·선택
- 전체 대본 복사
- 이미지·썸네일 다운로드
- 작업 전체 저장

**완료 기준:** 대본, 장면 이미지, 썸네일을 영상 편집에 바로 사용할 수 있다.

### 7단계 — 안정화

- ChatGPT·Gemini 화면 변경 대응
- 대용량 이미지 메모리·저장 공간 점검
- 생성 중 사이드패널 종료·재시작 복구
- 장면 삭제·정렬 중 작업 충돌 방지
- 권한과 회원 등급 적용

## 17. 구현 전에 추가로 결정할 사항

아래는 아직 최종 확정하지 않은 안건이다.

1. `4 · 유튜브 작성`의 사용 권한을 블로그 회원 권한과 같게 할지, 별도 권한으로 둘지
2. 첫 배포에서 쇼츠와 일반 영상을 동시에 열지, 쇼츠부터 먼저 열지
3. 직접 이미지 API를 첫 버전에 포함할지
4. ChatGPT·Gemini에서 전체 장면 자동 생성을 허용할지, 처음에는 한 장면씩 확인할지
5. 공실뉴스 브랜드형의 최종 색상·글꼴·로고 위치

## 19. 이번 계획의 범위 밖

다음 기능은 확장 가능성을 열어두되 이번 1차 계획에는 포함하지 않는다.

- 완성 영상을 유튜브 채널에 자동 게시
- 배경음악 저작권 검사와 자동 삽입
- AI 아바타 또는 실제 인물 립싱크
- 완전 자동 영상 편집과 렌더링
- 조회수 예측과 제목 A/B 테스트 자동 운영
- 댓글 자동 응답
