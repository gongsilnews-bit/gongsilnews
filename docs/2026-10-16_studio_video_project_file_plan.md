# 동영상제작 프로젝트 파일(.gsvideo) — 더블클릭 열기 · 회원끼리 주고받기 계획

- 날짜: 2026-10-16
- 결정: 사장님 — **편집 기능 개발을 먼저 마치고**, 이 계획은 그 뒤 **첫 배포 전에** 진행한다.
- 관련: [동영상 편집기 계획서](2026-10-15_studio_video_editor_plan.md)

---

## 1. 왜 필요한가

1. **더블클릭으로 열기** — 지금은 [프로젝트 열기]에서 폴더 안의 `project.json`(JSON 원본 파일)을 찾아 골라야 한다. 회원에게 어렵다.
2. **회원끼리 주고받기** — 다른 부동산 회원에게 프로젝트를 보내 이어서 편집하게 하고 싶다. 지금 방식으로는 안 된다.
   - 프로젝트에 **보낸 사람 PC의 파일 위치**(예: `C:\Users\…\Videos\화면 녹화\…mp4`)가 적혀 있어서 받는 PC에는 그 파일이 없다.
   - 내 자료의 사진·영상, 배경 음악은 프로젝트 폴더 **밖**에 있어서 폴더만 보내면 빠진다.

## 2. 지금 구조 (2026-10-16 기준)

```
내 문서\공실뉴스 스튜디오\영상\<프로젝트 이름>\
  project.json     ← 프로젝트 내용 (클립·애셋·설정)
  autosave\        ← 자동 저장 기록 (5분마다, 10개까지)
  voice\           ← AI 목소리 파일
  assets\          ← 받은 자료 (무료 자료 등)
  audio\           ← 받아쓰기용 소리
  output\          ← 완성 영상
```

- 코드: `studio-app/src/video/project.js` (create · open · save · saveAs · writeProject)
- 파일 열기 허용: `studio-app/src/video/media.js` — 앱을 다시 켜면 허용 목록이 비므로, 주소를 줄 때마다 등록한다.
- 다른 이름으로 저장(10-16 추가): 폴더를 통째로 복사, 폴더 안 파일 위치만 새 폴더로 고친다. 폴더 밖 파일은 원래 위치를 같이 쓴다 → **같은 PC 안에서만 유효**.

## 3. 설계 — 확장자 `.gsvideo` 하나, 쓰임 두 가지

| 종류 | 어디에 | 안에 든 것 | 더블클릭하면 |
|---|---|---|---|
| **작업용** | 프로젝트 폴더 안 `「이름」.gsvideo` | 프로젝트 내용(JSON) — `project.json` 과 같은 내용 | 그 자리에서 바로 편집 화면 |
| **보내기용** | 회원이 고른 곳 (바탕 화면 등) | zip 묶음: 프로젝트 + 쓰는 파일 전부 | 내 PC에 풀고 편집 화면 |

- 앱은 파일 앞부분을 보고 구별한다 (zip 이면 보내기용, JSON 이면 작업용). 회원은 그냥 더블클릭만 한다.
- `project.json` 은 계속 같이 쓴다 → **예전 앱(0.1.3)과 예전 프로젝트가 깨지지 않는다.** 예전 프로젝트는 한 번 열어 저장하면 `.gsvideo` 가 생긴다.

### 3-1. 작업용 + 더블클릭 열기 (1단계)

- `writeProject` 가 `project.json` 과 함께 `「이름」.gsvideo` 도 쓴다. 폴더 이름을 바꿔도 폴더 안의 `.gsvideo` 아무거나 찾는다.
- [프로젝트 열기] 창: `.gsvideo` 파일을 고르게 (지금의 `project.json` 도 계속 받는다).
- 더블클릭 흐름:
  - 앱이 꺼져 있으면: 실행 인자로 받은 경로 → 로그인 확인 → 동영상제작 → 그 프로젝트 열기.
  - 앱이 켜져 있으면: `second-instance` 로 경로를 받아 **켜져 있는 창에서** 연다 (창 하나 더 안 띄움).
  - 로그인 안 된 상태면 로그인 뒤 연다 (지금 `pendingDeepLink` 와 같은 방식으로 `pendingProject` 를 들고 있다).
- 앱 → 웹 전달: 앱이 `realty_admin?menu=video` 를 열고, 웹(VideoStudio)이 처음 뜰 때 `b.project.pending()` 으로 열 경로를 받아 간다. 이미 열려 있으면 `video:open-project` 신호로.

### 3-2. 보내기 묶기 (2단계)

- [파일] → **[다른 회원에게 보내기]** → 저장할 곳·이름 고르기 → 묶기 전에 **전체 용량** 보여 주기 → `.gsvideo`(zip).
- 묶는 것: 프로젝트가 쓰는 **모든 파일** — 클립 화면(사진·영상), 촬영 원본, AI 목소리, 배경 음악·음악 애셋, 사진 올리기, 받아쓰기 소리는 빼도 됨(다시 만들 수 있음).
- 묶음 안에서는 파일 위치를 **상대 위치**로 바꿔 적는다 (`media/xxx.mp4`).
- 파일을 모으는 함수는 **필드 목록을 손으로 적지 말고** 프로젝트 전체를 훑어 "파일 경로인 값"을 모은다 → 나중에 기능(영상 올리기·효과음 등)이 늘어도 빠지지 않게.
- 편집용 사본(`edit`)·썸네일은 묶지 않는다 (받는 쪽에서 다시 만든다) → 용량 절약.

### 3-3. 받아서 풀기 (3단계)

- 보내기용 `.gsvideo` 를 더블클릭(또는 [프로젝트 열기]) → `내 문서\공실뉴스 스튜디오\영상\받은 프로젝트\「이름」` 에 풀기 → 상대 위치를 그 PC의 실제 위치로 바꾸기 → 편집 화면.
- 같은 이름이 있으면 `_2`, `_3`.
- 받은 자료는 받는 사람의 내 자료에도 보이게 할지 → **배포 전 결정**.
- 망가진 파일·중간에 끊긴 파일이면 "파일이 손상됐어요, 다시 받아 주세요".

## 4. 배포 때 지킬 것

1. **더블클릭 연결은 설치판만** — `package.json` 의 `build.fileAssociations` 에 `.gsvideo`(이름 "공실뉴스 영상 프로젝트", 앱 아이콘)를 넣는다. 설치 프로그램(NSIS)이 윈도우에 등록하고, 자동 업데이트도 설치 프로그램을 다시 돌리므로 업데이트만 받으면 생긴다.
2. **개발판은 등록하지 않는다** — `gongsilstudio://` 와 같은 이유 (개발판이 설치판 연결을 빼앗는다). 개발 시험은 실행 인자로 경로를 넘겨서.
3. **웹 먼저, 앱 나중** — 편집 화면은 웹(Vercel), 파일 받기는 앱(자동 업데이트). 한쪽만 올라가도 오류 없게:
   - 웹은 새것·앱은 예전 것 → 새 단추는 "앱을 업데이트해 주세요" 안내 (`saveAs` 처럼 다리 함수가 없으면).
   - 앱은 새것·웹은 예전 것 → 동영상제작 첫 화면까지만 연다.
4. **받는 회원 앱이 예전 버전**이면 보내기용을 못 연다 → 안내 문구.
5. 영상이 들어가면 파일이 커진다 → 나중에 **"영상 용량 줄여서 보내기"** 를 추가 (이번 범위 아님).

## 5. 묶음 형식

- 표준 **zip** (작은 압축 도구 `yazl`·`yauzl` 를 앱에 추가). 큰 영상도 흘려 쓰기로 처리, 4GB 넘는 파일도 됨(zip64).
- 영상·사진은 이미 압축돼 있으므로 **압축 없이 담기**(store) → 빠르게.
- 묶음 안 첫 파일 `gsvideo.json`: `{ "type": "gongsil-video-package", "v": 1, "app": "<앱 버전>", "name": "<프로젝트 이름>" }` → 앱이 형식·버전을 확인.

1. (지금) 편집 기능 개발 계속

5. 웹 배포 → 앱 새 버전 배포
