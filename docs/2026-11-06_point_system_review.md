## 2. 오늘 나온 일 — "1번 썼는데 9줄, 모두 -0P"

회원 suppliant@daum.net (김동현) 실제 기록:

| 시각 (한국) | 기록 |
|---|---|
| 11-06 08:57:09 | 관리자지급 +5,000P → 잔액 5,000 |
| 11-06 09:00:56.5 ~ 09:00:59.0 | AI 목소리 9건, 일반 포인트 0P, 목소리 전용 45·40·40·39·39·38·45·30·52P |

- 회원은 [목소리 만들기]를 1번 눌렀다.
- 쇼츠는 클립마다 문장을 따로 만들기 때문에 서버에 요청 9개가 2.5초 안에 들어갔다 ([webBridge.ts:450-466](../src/components/admin/studio-video/webBridge.ts#L450-L466)).
- 서버는 요청마다 기록을 1줄씩 남긴다 → 9줄.
- 9문장 합계 368P는 목소리 전용에서 빠졌다. 관리자가 준 5,000P는 그대로다. 그래서 줄마다 "-0 P"로 보인다.
- 금액 계산 자체는 맞다. 하지만 회원 화면에서는 틀린 것처럼 보인다.
- 목소리 전용 남은 양(4,632P)은 포인트 화면 어디에도 나오지 않는다.

## 3. 확인된 문제 (위험한 순서)

### 문제 1. 포인트 서버 기능을 누구나 부를 수 있다 — 가장 위험
[point.ts](../src/app/actions/point.ts) 는 `"use server"` 파일이다. 이런 함수는 웹에서 바로 부를 수 있는 공개 통로가 된다.
그런데 아래 함수들이 **부르는 사람이 누구인지 확인하지 않는다.**

| 함수 | 할 수 있는 일 |
|---|---|
| `adminAdjustPoints(memberId, amount, reason)` | 아무 회원에게나 포인트를 넣거나 뺀다 |
| `updatePointSetting(key, value)` | 수수료·등급별 한도·권한 값을 바꾼다 |
| `transferPoints(fromId, toId, amount)` | 보내는 사람 id를 마음대로 넣어 남의 포인트를 옮긴다 |
| `getPointTransactions`, `getAllMembersWithBalance` | 전체 회원의 이름·이메일·잔액·거래를 읽는다 |

화면에서는 최고관리자에게만 버튼이 보이지만, 화면을 거치지 않고 부르면 막을 장치가 없다.

### 문제 2. 기자 응원이 잔액을 덮어쓴다
[subscription.ts:137](../src/app/actions/subscription.ts#L137) — 누군가 기자를 응원하면 그 기자의 `point_balance` 를 **응원 수로 바꿔 버린다.**
- 예: 기자 잔액이 5,000P이고 응원이 3개가 되면 잔액이 3P가 된다. 거래 기록도 남지 않는다.
- 지금 응원 기록은 12건 있다. 응원받은 기자의 잔액이 이미 바뀌었을 수 있다 → 따로 확인이 필요하다.

### 문제 3. 동시에 쓰면 차감이 덜 된다
모든 곳이 "잔액 읽기 → 계산 → 새 잔액 쓰기"를 따로 한다.
- 요청 두 개가 동시에 오면 둘 다 같은 잔액을 읽고, 나중 것이 앞의 것을 덮는다 → 한 번만 빠진 것처럼 남는다.
- AI 목소리는 문장 9개가 거의 동시에 오므로 일반 포인트에서 빠질 때 실제로 일어날 수 있다.
- 목소리 전용 5,000P 한도도 같은 이유로 조금 넘겨 쓸 수 있다.
- 보내기·특강도 잔액 바꾸기와 기록 남기기가 따로라서, 중간에 실패하면 잔액과 기록이 어긋난다.

### 문제 4. 화면에 있는 정책 중 실제로 작동하지 않는 것
관리자 포인트 화면에는 아래 값이 보이지만, 이 값을 읽어서 포인트를 주거나 빼는 코드가 없다.

| 설정 | 화면 설명 | 지금 값 | 실제 |
|---|---|---|---|
| SIGNUP_BONUS | 가입 축하 포인트 | 1,000 | 지급 안 됨 |
| VACANCY_REWARD | 공실 등록 보상 | 500 | 지급 안 됨 |
| COMMISSION_RATE | 콘텐츠 판매 수수료 | 20% | 특강 수익을 강사에게 100% 줌 |
| CHARGE_RATIO | 1원당 포인트 | 1 | 결제 충전 기능 없음 |

### 문제 5. 하루 보내기 한도 날짜가 한국 시간이 아니다
`transferPoints` 의 "오늘"이 서버 시간(UTC) 0시 기준이다. 한국 시간 오전 9시에 하루가 바뀐다.

## 회의 결정 (11-06)
- **포인트는 통합으로 관리한다** — 목소리 전용 같은 따로 주머니를 두지 않고, 회원 포인트는 잔액 하나.
- **지금은 AI 목소리만 포인트에서 빠진다.** 목소리 전용 5,000P 주머니는 없앴다 → 회원 잔액에서 바로 (적용: [eleven/route.ts](../src/app/api/studio/video/eleven/route.ts)).
- **정확하게 빠지게** — 잔액을 읽은 값 그대로일 때만 빼고, 다른 문장이 먼저 뺐으면 다시 읽어 뺀다. 여러 문장이 동시에 와도 덜 빠지지 않는다.
- **수정해도 수정한 만큼** — 문장을 고치거나 [다시 만들기]를 누르면 그 문장만 새로 만들고 그 문장 글자 수만큼 빠진다. 안 고친 문장은 저장해 둔 소리를 다시 쓰므로 빠지지 않는다.
- 나머지(1~9번)는 추후 사장님이 정한다.
- **앞으로 계획**: 특강(강의)부터 포인트 쓰는 곳을 모두 이 잔액 하나로 통합한다 ("나중에 강의부터 다 통합할꺼야"). 특강은 지금도 같은 잔액(`members.point_balance`)을 쓰지만, 동시에 쓸 때 정확하게 빠지게 하는 처리와 기록 모양은 목소리와 같은 방식으로 맞춘다.
- 지난 "목소리 전용" 기록은 소급해서 빼지 않는다 — 앞으로 만드는 것부터.
- **검증 (09:35, suppliant@daum.net 로컬)**: 10문장 377자 → 377P 차감, 5,000 → 4,623P, 줄마다 잔액이 빠짐없이 이어짐.
- **목소리 한 번 만들기 = 화면 1줄** ("그렇게 해줘"): 장부는 문장마다 1줄 그대로, 한 번 만들기에 묶음 번호(`reference_id`)를 붙이고 포인트 화면이 같은 묶음을 "AI 목소리 · 10문장 377자 -377P"로 합쳐 보여 줌. 누르면 문장별로 펼침. 15초 넘게 쉬었다 다시 만들면 새 줄. 묶음 번호 없는 예전 기록은 1줄씩. 코드: [pointGroup.ts](../src/utils/pointGroup.ts), [webVoice.ts](../src/components/admin/studio-video/webVoice.ts)

## 4. 회원이 알기 쉽게 — 화면 원칙 (안)

사장님 말씀 (11-06): "회원들이 알기 쉽게 사용할 수 있어야 해"

### 원칙
1. **누른 횟수 = 기록 줄 수** — 회원이 1번 했으면 기록도 1줄. 안쪽에서 몇 번 나눠 처리했는지는 회원에게 보이지 않는다.
2. **"-0 P"는 절대 보이지 않게** — 실제로 빠진 포인트가 어디서 얼마인지 그대로 적는다.
3. **포인트 주머니는 이름을 붙여 따로 보여 주기** — "내 포인트"와 "이번 달 목소리 전용"을 섞지 않는다.
4. **쓰기 전에 얼마인지, 쓴 뒤에 얼마 남았는지** — 만들기 버튼 옆에 미리, 끝나면 남은 양을 바로.
5. **회원 말로 적기** — "SPEND", "P2P전송", "특강수강:" 같은 안쪽 말 대신 "보냄", "특강 수강"처럼.

### 포인트 화면 (안)
```
┌ 내 포인트 ───────────┐  ┌ 이번 달 목소리 전용 ──────┐
│  5,000 P             │  │  4,632 P 남음 / 5,000 P   │
│  보내기·특강에 사용   │  │  AI 목소리에만 · 매달 1일 새로 │
└──────────────────────┘  └───────────────────────────┘

거래 내역
  AI 목소리 · 쇼츠 9문장 368자        목소리 전용 -368 P
  11. 6. 오전 9:00                    내 포인트 5,000 P 그대로
  ────────────────────────────────────────────────
  관리자 지급                                  +5,000 P
  11. 6. 오전 8:57                         잔액 5,000 P
```
- 목소리 전용과 내 포인트에서 함께 빠졌으면 두 줄로: "목소리 전용 -200P · 내 포인트 -168P".

### 목소리 만들기 화면 (안)
- 만들기 전: "이 영상 368자 → 목소리 전용에서 368P (남은 4,632P)"
- 모자랄 때: "목소리 전용이 120P 남았어요. 나머지 248P는 내 포인트에서 빠져요." → [계속] [취소]
- 끝난 뒤: "368P 사용 · 목소리 전용 4,632P 남음"

## 5. 결정할 것

1. **포인트 서버 기능에 본인·최고관리자 확인 넣기** — 문제 1. 가장 먼저 할 것을 권고.
2. **응원과 포인트 떼어 내기** — 응원 수는 따로 세고 `point_balance` 는 건드리지 않게. 이미 바뀐 기자 잔액은 기록을 보고 되돌릴지 정해야 함.
3. **잔액 바꾸기를 데이터베이스에서 한 번에** — 차감·기록을 한 덩어리로 처리해서 동시에 써도 정확하게 (문제 3).
4. **AI 목소리 기록을 "한 번 만들기 = 한 줄"로**
   > AI 목소리 · 쇼츠 9문장 368자 · 목소리 전용 -368P
   > 잔액 5,000P · 목소리 전용 남음 4,632P
5. **포인트 화면 위쪽에 목소리 전용 남은 양 보여 주기** — "이번 달 목소리 전용 4,632P / 5,000P"
6. **작동하지 않는 정책 4개** — 실제로 만들지, 화면에서 숨길지.
7. **목소리 전용 포인트를 따로 저장할지** — 지금은 기록 글을 읽어서 계산한다. 기록 글 모양이 바뀌면 계산이 틀어진다.

---

9. **통합 뒤 매달 5,000P** — 권고: 매달 1일 잔액에 +5,000P 넣고 기록 "공실뉴스부동산 이달 포인트 +5,000P". 어디에나 쓸 수 있고 남으면 다음 달로 넘어감. 보내기로 남에게 넘길 수 있게 되는 점은 확인 필요.
8. **4장 화면 안대로 갈지** — 포인트 화면 두 칸, 거래 내역 말, 목소리 만들기 전·후 안내.
