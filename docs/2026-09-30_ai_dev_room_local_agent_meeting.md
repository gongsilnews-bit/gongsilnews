# 🛠️ AI 개발실: 오류접수 → 로컬 에이전트 → GitHub 자동 수정 회의록

**일시:** 2026년 09월 30일 (수)
**참석자:** 사장님, Claude (AI 파트너)
**회의 주제:** 공실뉴스 관리자 화면에 오류·수정 요청을 한국어로 등록하면, 사장님 PC의 로컬 AI 에이전트가
가져가서 코드를 고치고, 빌드로 검증한 뒤 GitHub 브랜치에 올려 승인을 기다리게 한다.
AI API 키 없이, 이미 쓰고 있는 Claude Code를 그대로 활용한다.

## 0. 결정 요약

| 항목 | 결정 |

| GitHub 반영 | **브랜치까지만 자동 push** (`bug/BUG-2026-001`). main 병합은 사장님 **[승인]** 으로만 |

| 화면 위치 | 관리자 **AI 비서실 → 4번째 탭 "AI 개발실"** (현황판·업무 회의실·규칙 설정 다음) |
| 코드 위치 | 관리자 코드와 섞지 않고 **`src/devroom/` 별도 폴더**. 관리자 쪽은 탭 연결 2줄만 추가 |
| 일간 업무 보고 | 쓰지 않는 기능이라 **화면·서버 코드 모두 삭제** (기존 DB 기록은 보존) |

## 1. 현재 환경 (회의 중 확인)

- 스택: Next.js 16 + Supabase + Vercel + GitHub (`gongsilnews-bit/gongsilnews`)
- **Claude Code 2.1.109 설치되어 있음** → 로컬 에이전트로 바로 사용 가능
- **GitHub CLI(`gh`) 미설치** → PR 생성용으로 설치 필요 (`winget install GitHub.cli` 후 `gh auth login`)
- main에 push하면 Vercel이 실서버에 바로 배포하는 구조 → **main 자동 push를 금지하는 이유**

## 2. 전체 흐름

```
[공실뉴스 관리자 > AI 개발실]  사장님이 작업 등록 (종류, 내용, 발생 URL, 스크린샷)
        ↓  Supabase dev_tasks 테이블에 저장 (상태: 접수)
[로컬 Agent Runner]  30초마다 GET /api/devroom/tasks
        ↓  새 작업 발견 → 상태: 작업중
  ① git worktree로 별도 폴더 + 브랜치 생성 (bug/BUG-2026-001)
  ② 게시글을 "작업지시서"로 바꿔 claude -p 실행
  ③ npm run build 로 검증
  ④ commit → 브랜치 push → PR 생성
        ↓
[Vercel]  브랜치 미리보기 주소 자동 생성
        ↓  POST /api/devroom/tasks/{id}/result
[AI 개발실]  원인·수정 파일·커밋·PR·미리보기 링크 기록 → 상태: 승인대기
        ↓
  [승인]      → main 병합 → Vercel 실서버 배포 → 상태: 반영완료
  [반려+사유] → 같은 브랜치에서 사유를 반영해 재작업
```

## 3. 작업지시서 형식

게시글을 그대로 에이전트에 넘기지 않고, Runner가 아래 형식으로 바꿔서 넘긴다.

```
작업번호: BUG-2026-001
종류: 오류수정
문제: 모바일 공실 상세페이지에서 AI 기사작성 버튼이 동작하지 않는다.
관련 URL: /gongsil/view/65023
재현 방법: 모바일 → 상세페이지 → AI 기사작성 클릭
첨부: (스크린샷 파일 경로)

작업:
1. 관련 코드를 찾는다.
2. 원인을 분석한다.
3. 최소 범위로 수정한다.
4. 기존 기능에 영향이 없는지 확인한다.
5. npm run build 를 실행해 통과시킨다.
6. 원인·수정 파일·변경 내용을 요약해 보고한다.
원인을 확신할 수 없거나 재현에 로그인·실데이터가 필요하면 수정하지 말고 원인 분석만 보고한다.
```

프로젝트 규칙(`AGENTS.md`, `CLAUDE.md`)은 작업 폴더에 그대로 있으므로 에이전트가 자동으로 따른다.

## 4. 상태값

| 상태 | 의미 |
|---|---|
| `접수` | 등록됨, PC가 가져가기 전 |
| `작업중` | Runner가 가져가서 수정·빌드 중 |
| `승인대기` | 브랜치 push·PR 완료, 미리보기 링크 있음 |
| `승인됨` | [승인] 누름 → PC 에이전트가 PR 을 main 에 병합하는 중 (병합 실패 시 승인대기로 되돌림) |
| `반영완료` | 승인 → main 병합 → 배포됨 |
| `반려` | 사유 입력 → 같은 브랜치에서 재작업 대기 |
| `실패` | 빌드 실패 또는 원인 분석만 가능. 로그 첨부 |

반려 → 사유 반영 재작업은 **기사 반려 → 재작성**과 같은 방식이다.

### 4-1. 대화·진행 상황 (첫 시험 후 추가)

- **작업마다 대화창**: 에이전트는 시작·결과·질문을 남기고, 사장님이 승인대기·실패·반영완료 작업에 메시지를 보내면 그 내용을 반영해 다시 작업한다(`dev_task_messages` 테이블). 별도 [반려] 버튼 대신 대화로 피드백한다.
- **모르면 모른다고**: 요청이 모호하거나 원인을 확신할 수 없으면 추측으로 고치지 않고 대화창에 ❓질문을 남긴다.
- **실시간 진행 상황**: 작업중에는 "파일 보는 중 / 수정 / 빌드 중"이 게시판에 몇 초 간격으로 올라온다.
- **속도**: 기본 모델은 Sonnet (첫 시험에서 Opus 로 약 9분). 더 꼼꼼히 할 때만 `.env` 에 `CLAUDE_MODEL=opus`.
- 게시판은 실서버(Supabase)라 밖에서·휴대폰으로도 보인다. PC 는 켜져 있고 Runner 만 돌면 된다.

## 5. 만들 것

### 5-1. DB: `dev_tasks` 테이블

| 컬럼 | 내용 |
|---|---|
| `id`, `task_no` | 내부 번호, `BUG-2026-001` 형식 번호 |
| `type` | 오류수정 / 기능추가 / 디자인수정 / 긴급수정 |
| `title`, `description`, `page_url`, `repro_steps` | 요청 내용 |
| `attachments` | 스크린샷 (Supabase Storage 경로) |
| `status` | 4장의 상태값 |
| `branch`, `commit_sha`, `pr_url`, `preview_url` | GitHub·Vercel 결과 |
| `result_summary`, `changed_files`, `log` | 원인·수정 내용·실행 로그 |
| `reject_reason` | 반려 사유 |
| `created_by`, `created_at`, `started_at`, `finished_at` | 기록 |

### 5-0. 폴더 구조

```
src/devroom/                  AI 개발실 전용 폴더
  ├─ DevRoomBoard.tsx          게시판 화면 (등록·목록·상세·승인/반려)
  ├─ actions.ts                저장·조회·승인·반려 처리
  └─ types.ts                  상태값·작업 형식 정의
supabase/migrations/20260930_create_dev_tasks.sql   dev_tasks 테이블 (프로젝트 SQL 모음 규칙을 따름)
src/app/api/devroom/tasks/    Runner 접속 주소 (Next.js 규칙상 이 위치 필수)
scripts/devroom-runner/       사장님 PC에서 돌아가는 Runner
```

기존 `/api/agents`(AI 비서실용)와 헷갈리지 않게 API 이름은 `devroom`으로 한다.

### 5-2. 관리자 화면: AI 비서실 → AI 개발실 탭 (최고관리자 전용)

- 작업 등록 폼 (종류 선택, 내용, URL, 재현 방법, 스크린샷)
- 작업 목록 + 상태 표시
- 상세: 처리 결과, 수정 파일, 미리보기 링크, PR 링크, [승인] / [반려] 버튼

### 5-3. 내부 API (에이전트 전용 토큰 필수)

- `GET /api/devroom/tasks` — 처리할 작업 1건 가져오기 (가져가는 순간 `작업중`으로 바꿔 중복 처리 방지)
- `POST /api/devroom/tasks/{id}/result` — 처리 결과 보고

### 5-4. 로컬 Agent Runner

- 위치: 저장소 안 `scripts/devroom-runner/` (GitHub에 이력이 남도록)
- 30초마다 작업 확인 → worktree 생성 → `claude -p` 실행 → 빌드 → commit·push·PR → 결과 보고
- 실행 로그를 파일로 남김
- 승인된 작업은 `gh pr merge`로 병합 (GitHub 권한은 PC에만 둠)

| 단계 | 내용 |
|---|---|
| **1단계** | `dev_tasks` 테이블, AI 개발실 화면, API 2개, Runner (worktree → 수정 → 빌드 → 브랜치 push → PR → 결과 기록) |

| **3단계** | 회원 오류접수 연결 (사장님 검토 후 전달), 기능요청 게시판, 영상 제작 프로그램(studio2) 작업 연결 |

## 7. 주의사항·한계

- **PC가 켜져 있어야** 처리된다. 꺼져 있으면 `접수` 상태로 쌓였다가 켜지면 순서대로 처리한다.
- **빌드 1회에 몇 분** 걸리므로 동시 처리는 하지 않는다.
- **모든 오류를 고치지는 못한다.** 로그인·실데이터가 있어야 재현되는 오류는 원인 분석만 보고하고 `실패`로 남긴다.
- **보안:** 게시글이 곧 코드 수정 명령이 된다. 회원 글이 검토 없이 에이전트로 넘어가지 않게 하고,
  에이전트 전용 토큰은 `.env`에만 두고 저장소에 올리지 않는다.
- 에이전트는 `git push`, 배포, DB 변경 명령을 직접 실행하지 못하게 막는다.
