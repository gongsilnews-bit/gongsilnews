## 1. 에러가 잦은 이유 — 코드에서 보이는 것

사장님이 "에러가 많이 난다"고 하셨다. 우연이 아니라 **구조가 그렇게 돼 있다.**
지금 코드에서 확인된 원인이 여섯이다.

| # | 원인 | 왜 에러가 되는가 |
|---|---|---|
| 1 | **실패가 조용하다** | 추출이 실패하면 아무 말 없이 템플릿으로 내려간다. 에러 대신 **틀린 기사**가 나온다 |
| 2 | **남의 사이트 DOM 에 매달려 있다** | `#prompt-textarea`, `.ql-editor` … 챗GPT·제미나이가 화면을 바꾸면 그날로 죽는다 |
| 3 | **우리 사이트도 DOM 을 긁는다** | 사람 보라고 그린 표를 되읽는다. 디자인 한 번 손보면 값이 틀어진다 |
| 4 | **iframe + 보안헤더 제거** | 남이 켜 둔 `X-Frame-Options`·CSP 를 우리가 끈다. 저쪽이 조이면 빈 화면이 된다 |
| 5 | **받는 쪽이 없는데 성공이라고 말한다** | 전송 버튼이 확인 없이 "사진 4장 채워졌습니다" 배너를 띄운다 (6-1) |
| 6 | **2,460줄 한 파일** | `sidepanel.js` 하나에 전역 변수로 얽혀 있다. 한 군데 고치면 다른 데가 터진다 |

**1번이 가장 나쁘다.** 나머지는 터지면 보이기라도 하는데, 1번은 안 터진 척한다.
이번 정비의 원칙 하나를 여기서 못 박는다.

> **값이 없으면 지어내지 않는다. 그 줄을 비우고, 빨간 줄로 말한다.**

실제로 `sidepanel.js:1298` 에는 개발 중 샘플값 `"ACROHILLS논현"`, `"매매 15억"` 이
폴백으로 남아 있다. **추출이 실패하면 남의 단지 이름이 기사에 나간다.**

> 📌 **콘솔에 찍힌 에러 문구를 그대로 주시면** 이 표에 실제 건을 붙여 순서를 다시 잡겠습니다.
> 위 여섯은 코드만 읽고 확인한 것이라, 사장님이 실제로 겪으신 것과 다를 수 있습니다.

## 2. 그 전에 — 지금 열려 있는 문 두 개

기능 얘기가 아니다. **이미 배포된 상태에서 열려 있는 구멍**이다.

### 2-1. `/api/extension/publish` 는 아무나 부를 수 있다

`src/app/api/extension/publish/route.ts`

| 항목 | 현재 |
|---|---|
| CORS | `Access-Control-Allow-Origin: *` |
| 인증 | **한 줄도 없다.** 토큰·쿠키·키 아무것도 안 본다 |
| DB 접근 | `SUPABASE_SERVICE_ROLE_KEY` (RLS 통과) |
| 저장 | `status: 'APPROVED'` + 작성자를 **최고관리자로 자동 매핑** |

주소를 아는 사람이 `title` 과 `content` 만 담아 POST 하면 **공실뉴스 메인에
최고관리자 이름으로 기사가 즉시 올라간다.**

> 어제 회의 5-2 ① "접수 폼에 방어가 없다, 가장 급하다" 와 같은 종류인데
> **한 단계 더 나쁘다.** 접수 폼은 CRM 행이 조용히 늘어나는 것이고,
> 이건 **1면에 글이 실린다.**

### 2-2. `/api/extension/auth/me` 는 이메일만 주면 남의 등급을 알려준다

- `?email=` 쿼리만으로 그 회원의 `role`·`plan_type`·`max_articles_per_month` 를 준다.
  토큰 검증을 통과할 필요가 없다 — "개발/테스트 편의" 주석이 붙은 폴백이다
- 못 찾으면 **`role='ADMIN'` 계정을 대신 돌려준다.** 최고관리자 정보가 그대로 나간다
- 이 응답이 확장의 무료/유료 판정 전부다. 즉 **유료 차등이 사실상 없다**

### 2-3. 결정

| # | 안건 | 결정 |
|---|---|---|
| 1 | 인증 | 두 라우트 모두 **Supabase 액세스 토큰 필수.** 없으면 401 |
| 2 | 이메일 폴백 | **삭제.** 개발 편의는 `NODE_ENV !== 'production'` 으로만 |
| 3 | ADMIN 폴백 | **삭제.** 못 찾으면 401 |
| 4 | CORS | `*` → `chrome-extension://<확장ID>` 만 |
| 5 | 발행 권한 | 토큰 주인이 `role='ADMIN'` 일 때만 `APPROVED`, 그 외는 `PENDING` |
| 6 | 작성자 | 토큰의 주인. **최고관리자 자동 매핑 금지** |

확장 ID 를 고정하려면 `manifest.json` 에 `key` 를 박아야 한다. 안 그러면 다시
로드할 때마다 ID 가 바뀌어 **CORS 가 매번 깨진다 — 이것도 에러의 원인이 된다.**

## 3. 요구사항 2 — 매물 정보와 사진

### 3-1. 지금 값이 틀리게 들어온다

사이드패널 `소재지` 칸에 이렇게 들어와 있다.

```
서울 강남구 논현동 💡 위치 정보 안내 본 매물은 중개사의 요청으로 주소 및
상세 위치가 비공개 설정되어, 지도상에는 가까운 지하철역 또는 사거리 부근에
표시됩니다. 실제 건물 위치와 차이가 있으니 … 직접 문의해 주세요. -
```

원인은 뚜렷하다. `content.js` 의 `getValByLabel()` 은 **라벨 칸의 다음 형제 요소를
통째로 읽는다.** `GongsilDetailPanel.tsx:799` 의 소재지 값 칸 안에는 주소 밑에
**위치정보 안내 박스가 같이 들어 있다.** 안내 문구까지 딸려 온다.

면적도 어긋나 있었다 (패널: `793.4m²(240평)` / 매물: `102.5m²(31평)`).
형제 매칭이 실패하면 `fullText.match()` 정규식 폴백으로 떨어지면서
**화면 어딘가의 다른 숫자를 집는다.**

**여기서 생긴 오염이 그대로 기사 본문이 된다.** 안내 문구가 기사에 박히면
그건 곧 표시광고 문제다.

### 3-2. DOM 을 긁는 방식을 그만둔다

우리가 만든 화면인데도 **사람 눈에 보이라고 그린 표를 되읽고 있다.**

마침 `#detail-scroll-container` 에 이미 `data-vacancy-id` 와 `data-images` 가 붙어 있다.
**같은 자리에 기사에 필요한 값을 정식으로 얹으면 된다.**

| # | 안건 | 결정 |
|---|---|---|
| 1 | 통로 | `#detail-scroll-container` 에 `data-article-source` (JSON) 한 칸 |
| 2 | 만드는 곳 | `GongsilDetailPanel.tsx` — `prop` 에서 바로 직렬화. 화면 텍스트를 거치지 않는다 |
| 3 | 확장 | 그 JSON 이 있으면 **그것만 쓴다.** 없으면 **에러를 띄운다** (DOM 긁기로 몰래 내려가지 않는다) |
| 4 | 안내 문구 | 정식 통로에는 **애초에 들어가지 않는다** |
| 5 | 비공개 주소 | 주소 비공개 매물이면 JSON 도 시·군·동까지만. 기사도 거기까지만 |

담을 것 — 공실번호 · 종류 · 거래구분 · 금액 · 시/군/동 · 단지명 · 공급/전용면적 ·
층 · 방/욕실 · 방향 · 주차 · 관리비 · 입주가능일 · 옵션 · 테마 · 설명 ·
사진 URL 배열 · 좌표 · 주소공개여부.

### 3-3. 사진 4장 묶음은 지금 것을 그대로 쓴다

이미 잘 짜여 있다. 기사 한 건에 들어가는 사진은 언제나 이 넷이다.

| 순 | 사진 | 만드는 법 | 대표 |
|---|---|---|---|
| 1 | 실매물 등록 검증 | 공실열람 화면 16:9 크롭 캡쳐 | |
| 2 | 대표 실물 | 매물 등록 사진 1장 | ✓ |
| 3 | 위치 지도 | 지도 요소 캡쳐 (실패 시 카드 생성) | |

## 5. 요구사항 4 — 챗GPT·제미나이 (가장 큰 구멍)

### 5-1. 지금은 보내기만 하고 받아오지 않는다

`injectPrompt()` 는 프롬프트를 넣고 전송 버튼을 누른다. **거기서 끝이다.**
응답을 읽는 코드가 어디에도 없다.

그럼 미리보기의 글은 어디서 오는가 — `updatePreviewModelFromInput()` 이
**추출한 매물 값으로 확장 안에서 문자열을 조립한다.** 즉 지금 나오는 기사는
**AI 가 쓴 것이 아니다.** 사이드패널에 챗GPT 를 띄워 두는 것과 미리보기에 글이
나오는 것은 서로 아무 상관이 없다.

이것이 요구사항 4가 "반만 됨"인 이유이자, 1장 1번(조용한 실패)의 가장 큰 사례다.

### 5-2. iframe 을 버리고 탭으로 간다

`sidepanel.html:376-377` 은 챗GPT·제미나이를 `<iframe>` 으로 띄우고,
`rules.json` 이 그 응답에서 `X-Frame-Options` 와 CSP **헤더를 지운다.**

| 이유 | 설명 |
|---|---|
| 읽어올 수 없다 | 남의 출처 iframe 안은 확장 스크립트로도 못 읽는다. **응답을 못 받아오는 진짜 이유가 이것이다** |
| 깨지기 쉽다 | 두 서비스가 프레임 차단을 강화하면 그날로 빈 화면 |
| 남의 보안장치다 | 그쪽이 켜 둔 것을 우리가 끈다. 약관 문제로 번질 수 있다 |
| 이미 안 쓴다 | 프롬프트 주입은 `chrome.scripting` + `tabId` 로, **탭에다 하고 있다** |

**결정: `<iframe>` 둘과 `rules.json` 을 걷어낸다.** `declarativeNetRequest`
권한도 같이 뺀다. 사이드패널은 우리 화면만 그리고, AI 는 **옆 탭**에서 돈다.

### 5-3. 응답을 받아오는 길

| # | 안건 | 결정 |
|---|---|---|
| 1 | 방식 | 챗GPT·제미나이 탭에 붙는 **콘텐츠 스크립트**가 응답을 읽어 사이드패널로 보낸다 |
| 2 | 완료 판정 | `MutationObserver` + **마지막 변경 후 1.2초 조용하면 끝.** 스트리밍이라 "끝" 신호가 없다 |
| 3 | 파싱 | 프롬프트에서 ` ```json ` 블록으로 답하라고 못 박는다. 산문을 정규식으로 뜯지 않는다 |
| 4 | 실패했을 때 | **템플릿으로 조용히 내려가지 않는다.** "AI 응답을 못 받았습니다 — [붙여넣기]" 를 띄운다 |
| 5 | 수동 경로 | 응답 붙여넣기 칸을 항상 남긴다. 셀렉터는 언젠가 깨진다 |
| 6 | 이미지 | `importAiImageToKey()` 가 이미 있다. 같은 길로 4장 중 원하는 자리에 꽂는다 |

### 5-4. 셀렉터는 한 곳에 모은다

`#prompt-textarea`, `button[data-testid='send-button']`, `.ql-editor` …
화면이 바뀌면 전부 죽는다. **`aiSelectors.js` 한 파일**로 모으고, 못 찾으면
**조용히 실패하지 말고 사이드패널에 빨간 줄을 띄운다.** 그래야 사장님이 "에러가
난다"가 아니라 "챗GPT 입력칸을 못 찾는다"를 보시게 된다.

## 6. 요구사항 5 — 옆 화면 기사작성기에 자동 적용

### 6-1. 지금 줄이 끊겨 있다

전송 버튼은 세 가지를 동시에 던진다.

```
localStorage['gongsil_ai_incoming_draft'] = JSON
window.dispatchEvent('gongsil_ai_inject_draft')
window.postMessage({ type:'GONGSIL_AI_INJECT_DRAFT' })
```

**`src/` 전체에서 이 셋을 받는 코드가 없다.** 쓰는 곳만 둘(확장,
`GongsilDetailPanel.tsx:413` 의 `✨ AI 기사작성` 버튼) 있고 읽는 곳이 0이다.

실제로 채워지는 것은 마지막 안전망인 DOM 직접 입력, 즉 **제목과 부제목 두 칸뿐**이다.
본문과 사진 4장은 `localStorage` 에 넣어 두고 아무도 꺼내지 않는다.

> 화면에 뜨는 **"제목, 본문, 사진(총 4장)이 채워졌습니다!"** 파란 배너는
> **아무것도 확인하지 않고 무조건 뜬다.** 안 들어간 걸 들어갔다고 말한다.
> 1장 5번이 이것이다.

### 6-2. 결정 — 받는 쪽을 만든다

| # | 안건 | 결정 |
|---|---|---|
| 1 | 받는 곳 | `NewsWriteForm.tsx` 에 수신부 하나 |
| 2 | 통로 | **`postMessage` 하나로 통일.** 셋을 다 두면 어느 것이 먹었는지 모른다 |
| 3 | `localStorage` | 폼이 아직 안 떴을 때를 위한 **대기실로만.** 마운트되면 꺼내 쓰고 **바로 지운다** |
| 4 | 출처 검사 | `event.source === window` 확인. 아무 페이지나 폼을 채우면 안 된다 |
| 5 | 사진 | `photoFiles` 를 그대로 받는다. `file:null` + `preview` 규격은 이미 맞다 |
| 6 | 덮어쓰기 | 폼에 이미 쓴 내용이 있으면 **묻는다.** 말없이 덮지 않는다 |
| 7 | 배너 | **폼이 실제로 받았다고 답신했을 때만** 띄운다 |

### 6-3. `GongsilDetailPanel` 의 `✨ AI 기사작성` 도 같이 산다

그 버튼도 같은 키에 넣고 `/admin?...` 을 연다. 받는 쪽이 생기면
**확장이 없어도 공실열람에서 바로 초안이 넘어간다.** 손대는 김에 같이 붙는다.

### 6-4. 확인이 필요합니다

요구사항 5의 "옆화면에 공실등록을 띄어놓으면" 을 두 가지로 읽을 수 있습니다.

- **(가)** 옆에 **기사쓰기** 화면을 띄워 두면 초안이 자동으로 들어간다 → 6-2 그대로
- **(나)** 옆에 **공실열람 매물**을 띄워 두면 확장이 알아서 그 매물을 물어온다
  → 탭 전환 감지 + 자동 재추출이 더 붙는다

버튼 이름이 `옆 화면 기사작성기로 전송` 이라 **(가)로 보고 계획했습니다.**

## 7. 화면에서 빼기로 한 것

사장님이 미리보기 화면에 X 치신 두 곳이다. **둘 다 뺀다.**

| 뺄 것 | 이유 |
|---|---|
| **`네이버 블로그` 미리보기 기기 버튼** | 요구사항 다섯 개 어디에도 블로그가 없다. 미리보기 기기는 `모바일(375px)` · `PC 웹` 둘이면 된다 |
| **`기사 포함 사진 (총 4장)` 썸네일 줄** | 바로 아래 본문에 같은 사진 4장이 캡션까지 붙어 그대로 흐른다. **같은 것을 두 번 보여주면서, 클릭 규칙(클릭=대표지정 / ✕=교체)을 하나 더 외우게 한다** |

### 7-1. 겸해서 — 네이버 블로그 모드 전체를 들어낼 것을 권합니다

미리보기 버튼만 빼면 **블로그용 코드는 그대로 남습니다.** `sidepanel.js` 안에
듀얼 모드 분기(`switchDualMode`), 스마트에디터 서식 복사, 블로그 전용 템플릿과
해시태그 생성기가 얹혀 있고, 이것이 **2,460줄짜리 파일을 얽히게 만드는 가장 큰
덩어리**입니다. 1장 6번(한 군데 고치면 다른 데가 터진다)의 주범입니다.

**제 권고는 이번에 통째로 들어내는 것입니다.** 요구사항에 없고, 지우면 파일이
눈에 띄게 얇아져 나머지 고치는 일이 다 쉬워집니다. 나중에 필요해지면 그때는
정리된 틀(4장) 위에 **모드 하나 얹는 일**이 됩니다.

> **다만 기능을 지우는 일이라 사장님 확인 없이는 손대지 않겠습니다.**
> "미리보기 버튼만 빼고 블로그 기능은 남겨라" 하시면 그렇게 합니다.
