## 1. 흐름 (탭 4개)

```
1 · 시뮬레이션
   1단계 사진     [공실열람 페이지 이동] → [물건 가져오기] (매물 정보 + 등록 사진)
                  또는 [사진 직접 올리기]  →  쓸 사진 최대 3장 선택
   2단계 설계 조건 외장재 · 창호 · 색상 · 파사드 구성 · 간판/사인 · 조경 · 조명 / 버전 수 · 이미지 비율
   3단계 공사비 기준 전면 폭(m) · 층수 · 층고 · 외벽 면 수 → 외벽 면적 자동 계산 (공실 정보로 층수 미리 채움)
   4단계 AI 선택   Gemini(권장) / ChatGPT
   5단계 시뮬레이션
        ① [설계 지시서 요청]   AI 탭을 열고 프롬프트 1(설계 지시서 JSON)을 채운다
        ② [작성하기]           전송
        ③ [지시서 가져오기]     JSON 을 읽는다 (이미지 지시문 · 보존 규칙 · 사양 · 버전별 차이 · 주의 문구)
        ④ [예측 이미지 요청]    원본 사진을 AI 입력칸에 첨부하고 프롬프트 2(버전 n)를 넣어 전송
        ⑤ [이미지 가져오기]     완성된 예측 이미지를 받는다 → 버전 수만큼 ④⑤ 반복
   📋 결과표   현재 외관 / 예측 외관(버전별) · 디자인 사양표 · 차별화 포인트 · 제약/보존 규칙 ·
               예상 공사비(범위 + 항목별) · 주의 문구
               [결과표 이미지 저장] [예측 이미지 저장]
2 · 기사       결과표로 리모델링 기사 → 공실뉴스 기사쓰기 화면에 전송 (전·후 사진 포함)
3 · 블로그     결과표 + 기사로 네이버 블로그 글 → 블로그 글쓰기 화면에 전송
4 · 유튜브     결과표로 대본
```

- 결과표가 없으면 2·3·4 탭은 잠긴다.
- **기사·블로그·유튜브는 결과표에 있는 내용만 쓴다.** 결과표에 없는 자재·금액을 지어내지 않게 지시문에 박는다.
- 기사 작성기처럼 단계 사이마다 사람이 눈으로 확인하는 버튼을 둔다 (한 번에 몰아 누르지 않는다).

## 2. 가져오는 프롬프트 (웹 시뮬레이터 원문)

### 2-1. 프롬프트 1 — 설계 지시서 (글 → JSON)
역할 "건물 외관 리모델링 예측 시뮬레이터의 프롬프트 엔지니어". 사용자 입력 7항목 + 버전 수,
핵심 원칙 6가지(구조 보존·현실성·디테일·맥락 유지·개인정보 보호·한글 텍스트 금지), 출력 JSON.
원문은 `remodeling10/shared/remodel-spec.js` 의 `rmBuildSpecPrompt` 에 **글자 그대로** 옮긴다.

웹 시뮬레이터는 API 의 `responseSchema` 로 JSON 형식을 따로 넘겼다. 채팅 화면에는 그 방법이 없으므로
**같은 스키마를 글로 덧붙인다** (필드 이름·설명 원문 그대로):
`imagePrompt · constraints · designSpec{materials,colors,windows,signage,lighting,landscaping} ·
versionDiffsEn[] · versionDiffsKo[] · disclaimer`

> 웹 시뮬레이터와 다른 점 (지시문 본문 문장은 그대로):
> - 외장재를 영어 id(stone, ceramic…) 대신 다른 항목처럼 **한국어 이름**으로 넣는다.
> - 채팅 화면용으로 맨 끝에 한 줄씩 덧붙인다 — 프롬프트 1: "이미지는 아직 만들지 말고 JSON 하나만 출력",
>   프롬프트 2: "첨부한 현재 건물 사진을 원본으로 지금 이미지를 만들 것". API 는 형식을 따로 받았지만 채팅은 말로 알려야 한다.
> - **원문은 글자·공백 하나 바꾸지 않는다 (사장님 결정)**. 웹 시뮬레이터 파일과 기계 대조로 일치를 확인했다.
>   채팅 화면용 문장은 **원문 뒤에만** 덧붙인다.
> - **구도 유지 보충**: Gemini 가 올려다본 원본을 눈높이 시점으로 다시 그려 위층이 잘린 일이 있었다.
>   프롬프트 2 원문 뒤에 "[Additional note] 첨부 사진을 고칠 것 — 같은 카메라 위치·각도·구도, 모든 층이 보이게"를 붙이고,
>   프롬프트 1 원문 뒤에 "imagePrompt 에 카메라·렌즈·시점을 쓰지 말 것"을 붙였다.
>   "원본" 비율을 고르면 원문의 비율 자리(${o})에 "the same as the source photo" 가 들어간다 (문장은 원문 그대로).
> - 이미지 비율 기본값은 **원본(같은 구도)**. AI 추천은 **ChatGPT** (원본 사진을 고치는 방식이라 구도를 잘 지킨다).
> - 버전 수는 **1개로 고정**, 선택칸을 없앴다.

## 3. 예상 공사비

**AI 가 아니라 확장이 계산한다.** AI 는 계산된 숫자를 받아 글로만 쓴다.

```
외벽 면적(m²) = 전면 폭 × (층수 × 층고) × 외벽 면 수
창 면적       = 외벽 면적 × 30%
외장재        = (외벽 면적 − 창 면적) × 선택 외장재 단가 평균
창호          = 창 면적 × 선택 창호 단가 평균
파사드 구성   = 외벽 면적 × 선택 항목 m² 단가 합  (1층 통유리는 한 건당 금액)
간판·조명·조경 = 한 건당 금액 합
가설·철거·폐기물 = 위 합계 × 15~25%
→ 최저 ~ 최고 범위, 백만 원 단위 반올림
```

단가표 초안(`shared/remodel-cost.js`, 사장님 확정 전 초안 · 부가세·설계비·인허가 비용 제외):

| 외장재 (만원/m²) | 최저~최고 | 창호 (만원/m²) | 최저~최고 |
|---|---|---|---|
| 석재 | 25~40 | 알루미늄 시스템창호 | 35~55 |
| 세라믹 패널 | 20~32 | PVC 이중창 | 20~30 |
| 메탈 패널 | 15~25 | 커튼월 | 45~70 |
| 로이유리 커튼월 | 45~70 | 목재 프레임 | 40~60 |
| 벽돌 | 12~20 | 프로젝트 창 | 30~45 |
| 스타코 | 5~9 | 픽스 창 | 25~40 |
| 목재 사이딩 | 12~22 | | |

| 파사드 (만원/m² 추가) | 최저~최고 | 한 건당 (만원) | 최저~최고 |
|---|---|---|---|
| 수직 루버/핀 | 4~8 | 1층 전면 통유리 | 1,500~3,500 |
| 수평 루버 | 4~8 | LED 채널 사인 | 300~800 |
| 메탈 메쉬 | 6~12 | 백라이트 사인 | 400~1,000 |
| 입체 돌출/보이드 | 8~15 | 미니멀 레터링 | 200~600 |
| 비정형/곡선 | 10~20 | 돌출/플래그 사인 | 150~400 |
| | | 네온 사인 | 200~500 |
| | | 조명 항목당 | 300~1,200 |
| | | 조경 항목당 | 200~1,500 |

결과표·기사·블로그·유튜브 모든 곳에 **"대략적인 예상 공사비이며, 꼭 실질적인 확인이 필요합니다."** 를 붙인다.
