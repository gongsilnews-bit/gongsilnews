# 📋 물건접수장 → 부동산 원페이지 홈페이지 전환 회의록

**일시:** 2026년 09월 22일 (화)
**참석자:** 사장님, Claude (AI 파트너)
**회의 주제:** 중개사 서브도메인의 물건접수장을 원페이지 부동산 홈페이지로 확장하고,
주소를 전 중개사·사업자에게 일괄 발급하되 요금제로 개폐한다

---

## 1. 배경

### 1-1. 현재 상태 (As-Is)

중개사 서브도메인(`{아이디}.gongsilnews.com`)은 `src/app/sites/[subdomain]/IntakeClient.tsx`
한 파일로 그려지며, 구성은 **헤더 → 히어로 → 접수 폼 → CONTACT AGENT → 푸터**다.
접근은 유료 프리미엄 회원 전용(`getHomepageSettingsBySubdomain`)이고, 편집기
(`IntakeStudio.tsx`)는 색상 5종만 고르게 하고 배치는 잠가두었다.

### 1-2. 하루 전 결정과의 충돌

2026-09-21 커밋 `e0c5f7f7`에서 기사 섹션과 서브도메인 기사 상세 페이지를 의도적으로
제거했다. 사유는 "신뢰를 쌓으려 넣었으나 각각 폼 작성을 멈추게 하는 출구가 됐다"였다.
오늘 안건은 그 방향을 되돌린다.

### 1-3. 그럼에도 확장하는 이유

유료 회원에게 '접수 폼 한 장'은 상품성이 약하다. 중개사가 명함에 찍고 포털에 등록할 것은
'홈페이지'지 '접수 폼'이 아니다. 단, **한 페이지 밖으로 새지 않는다**는 원칙을 건다.

## 4. 주소 일괄 발급과 개폐

`src/middleware.ts:73`이 이미 `{sub}.gongsilnews.com/*` → `/sites/{sub}/*`로 rewrite 한다.
주소 형식은 손댈 것이 없다.

### 4-1. 일괄 발급 (주소 선점)

- **대상**: 중개사(REALTOR)·사업자(BIZ) 회원 **전원**. 무료 회원도 주소만 먼저 잡아둔다.
- **규칙**: 이메일 앞부분을 정제해 발급 (`gongsilmarketing@gmail.com` → `gongsilmarketing`).
  소문자·숫자·하이픈, 2~30자, 중복 시 접미 숫자. 쓸 수 있는 문자가 없으면 `gs-{짧은해시}`.
- **예약어 차단**: 현행 `checkSubdomainAvailable`에 예약어 목록이 없다.
  `www, api, m, admin, news, study, biz, flyer, sites, mail, static, cdn` 등이 발급되면
  메인 도메인 라우트와 충돌하므로 반드시 막는다.
- **백필**: 기존 회원 일괄 발급 일회성 스크립트 (`scripts/`).
- **영업 효과**: "사장님 주소는 `hong.gongsilnews.com`으로 잡혀 있습니다. 결제하시면
  오늘 열립니다" 라는 권유가 가능해진다.

### 4-2. 개폐 (문은 요금제가 연다)

- **자동**: `plan_type` + `plan_end_date`. 만료일이 지나면 그날로 닫힌다.
  검사 로직은 이미 `getHomepageSettingsBySubdomain`에 있다.
  요금제는 `src/app/admin/actions.ts:86` 한 곳에서 관리되므로 결제→개방이 자동으로 따라온다.
- **수동**: `homepage_settings.is_active`. 최고관리자가 개별로 강제 개폐.
- **데이터 보존**: 닫혀도 설정·사진·문구는 지우지 않는다. 재결제하면 **같은 주소로 그대로
  부활**한다. 끊으면 사라지고 넣으면 돌아오는 구조 자체가 해지 방어가 된다.

### 4-3. 닫혔을 때 보여줄 화면

현행은 "존재하지 않거나 비활성화된 홈페이지입니다" 한 장뿐이라, 만료된 중개사의 고객이
보면 폐업한 것처럼 보인다. 다음과 같이 분리한다.

| 상황 | 화면 | HTTP |
|------|------|------|
| 없는 주소 | 페이지를 찾을 수 없음 | 404 |
| 요금제 만료·수동 중지 | **일시적으로 중단된 페이지** 안내 + 공실뉴스 바로가기 | **503 + noindex** |

503으로 답해야 닫혀 있는 동안 검색 색인이 날아가지 않고, 재결제 시 검색 순위가 그대로
돌아온다. 404로 답하면 색인에서 제거된다.

### 4-4. 나중에 도메인을 사서 붙일 때

| 방식 | 내용 | 필요 작업 |
|------|------|-----------|
| **(A) 단순 포워딩** | 구입한 도메인을 DNS에서 서브도메인으로 넘김. 주소창에는 `{아이디}.gongsilnews.com`이 보인다 | **코드 변경 없음. 오늘도 가능** |
| **(B) 진짜 연결** | 주소창에 본인 도메인 유지, 검색도 본인 도메인으로 잡힘 | `custom_domain` 컬럼 + Vercel 도메인 등록 + middleware 수정 |

현행 middleware는 `.gongsilnews.com`만 잘라내므로(`middleware.ts:31`) 다른 도메인이
들어오면 주인을 못 찾는다. **이번에 `custom_domain` 칸과 조회 경로만 미리 깔아둔다.**
값이 비어 있으면 아무 일도 일어나지 않고, 나중에 (B)로 갈 때 페이지 코드는 손대지 않고
middleware와 Vercel 등록만 하면 된다.

### 4-5. ⚠️ 선행 확인 (코드 밖)

Vercel 프로젝트에 와일드카드 도메인 `*.gongsilnews.com`이 등록되어 있어야 한다.
개별 도메인만 등록된 상태라면 회원마다 수동 등록이 필요해 일괄 발급이 성립하지 않는다.

## 5. 편집기(IntakeStudio) 확장

| 패널 | 추가 항목 |
|------|-----------|
| 디자인 | 히어로 배경사진 업로드, 오버레이 밝기, 카드 모서리(라운드/각짐) |
| 섹션 | 매물 / 기사 on·off, 매물 노출 개수, 기사 노출 개수 |
| 회사정보 | 사무실 사진, 대표 사진 (현행 `agencies` 값 그대로 읽는 방식 유지) |

업로드는 기존 `uploadHomepageFile()` + `homepage_assets` 버킷을 그대로 쓴다.
저장은 `settings.intake` JSONB 병합 방식을 유지하므로 마이그레이션이 필요 없다.
미리보기는 지금처럼 실제 공개 컴포넌트를 그대로 렌더한다.

## 6. 구현 순서

| 단계 | 내용 | 산출 |
|---|------|------|
| 0 | `IntakeClient.tsx`(984줄) 섹션별 컴포넌트 분할 | 리팩토링 선행 |
| 1 | 우리 매물 섹션 + 매물 상세 새창 페이지 | `sites/[subdomain]/vacancy/[no]` |
| 2 | 기사 섹션 복구 + 기사 상세 새창 페이지 | `e0c5f7f7` 역방향 |
| 3 | 폼을 맨 아래로 이동, 앵커내비 · 모바일 하단바 | `IntakeClient.tsx` 재배치 |
| 4 | CONTACT AGENT에 지도 길찾기 배치 | `agencies.address` |
| 5 | 편집기 확장 (사진 업로드 · 섹션 on/off) | `IntakeStudio.tsx` |
| 6 | 일시중지 화면 분리 (503 · noindex) | `sites/[subdomain]/page.tsx` |
| 7 | 주소 자동 발급 + 예약어 + 백필 스크립트 + `custom_domain` 칸 | `homepage.ts`, `scripts/`, SQL |

섹션이 배로 늘어나므로 0단계 분할을 먼저 하고 시작한다.
7단계는 4-5의 와일드카드 확인이 끝난 뒤에 배포한다(코드 작업 자체는 무관하게 진행 가능).

## 7. 보류 항목

- **대표 소개·경력 섹션** — 이번 범위에서 제외. 필요해지면 `settings.intake`에 필드 추가.
- **중개 분야·서비스 안내** — 동일.
- **고객 후기** — 테이블이 없고 운영 부담이 커서 논의에서 제외.
- **middleware 단계의 만료 차단** — `middleware.ts`에 TODO로 남아 있으나, 페이지 단계의
  `isPremium` 검사가 막고 있어 급하지 않다. 다만 6단계에서 503 응답을 넣을 때 함께 본다.
