# 📋 물건접수장 → 부동산 원페이지 홈페이지 전환 회의록

**일시:** 2026년 09월 22일 (화)
**참석자:** 사장님, Claude (AI 파트너)
**회의 주제:** 중개사 서브도메인의 물건접수장을 원페이지 부동산 홈페이지로 확장하고,
주소를 전 중개사·사업자에게 일괄 발급하되 요금제로 개폐한다

---

## 1. 배경

### 1-1. 현재 상태 (As-Is)

중개사 서브도메인(`{아이디}.gongsilnews.com`)은 `src/app/sites/[subdomain]/IntakeClient.tsx`
한 파일로 그려지며, 구성은 **헤더 → 히어로 → 접수 폼 → CONTACT AGENT → 푸터**다.
접근은 유료 프리미엄 회원 전용(`getHomepageSettingsBySubdomain`)이고, 편집기
(`IntakeStudio.tsx`)는 색상 5종만 고르게 하고 배치는 잠가두었다.

### 1-2. 하루 전 결정과의 충돌

2026-09-21 커밋 `e0c5f7f7`에서 기사 섹션과 서브도메인 기사 상세 페이지를 의도적으로
제거했다. 사유는 "신뢰를 쌓으려 넣었으나 각각 폼 작성을 멈추게 하는 출구가 됐다"였다.
오늘 안건은 그 방향을 되돌린다.

### 1-3. 그럼에도 확장하는 이유

유료 회원에게 '접수 폼 한 장'은 상품성이 약하다. 중개사가 명함에 찍고 포털에 등록할 것은
'홈페이지'지 '접수 폼'이 아니다. 단, **한 페이지 밖으로 새지 않는다**는 원칙을 건다.

## 4. 주소 일괄 발급과 개폐

`src/middleware.ts:73`이 이미 `{sub}.gongsilnews.com/*` → `/sites/{sub}/*`로 rewrite 한다.
주소 형식은 손댈 것이 없다.

### 4-1. 일괄 발급 (주소 선점)

- **대상**: 중개사(REALTOR)·사업자(BIZ) 회원 **전원**. 무료 회원도 주소만 먼저 잡아둔다.
- **규칙**: 이메일 앞부분을 정제해 발급 (`gongsilmarketing@gmail.com` → `gongsilmarketing`).
  소문자·숫자·하이픈, 2~30자, 중복 시 접미 숫자. 쓸 수 있는 문자가 없으면 `gs-{짧은해시}`.
- **예약어 차단**: 현행 `checkSubdomainAvailable`에 예약어 목록이 없다.
  `www, api, m, admin, news, study, biz, flyer, sites, mail, static, cdn` 등이 발급되면
  메인 도메인 라우트와 충돌하므로 반드시 막는다.
- **백필**: 기존 회원 일괄 발급 일회성 스크립트 (`scripts/`).
- **영업 효과**: "사장님 주소는 `hong.gongsilnews.com`으로 잡혀 있습니다. 결제하시면
  오늘 열립니다" 라는 권유가 가능해진다.

### 4-2. 개폐 (문은 요금제가 연다)

- **자동**: `plan_type` + `plan_end_date`. 만료일이 지나면 그날로 닫힌다.
  검사 로직은 이미 `getHomepageSettingsBySubdomain`에 있다.
  요금제는 `src/app/admin/actions.ts:86` 한 곳에서 관리되므로 결제→개방이 자동으로 따라온다.
- **수동**: `homepage_settings.is_active`. 최고관리자가 개별로 강제 개폐.
- **데이터 보존**: 닫혀도 설정·사진·문구는 지우지 않는다. 재결제하면 **같은 주소로 그대로
  부활**한다. 끊으면 사라지고 넣으면 돌아오는 구조 자체가 해지 방어가 된다.

### 4-3. 닫혔을 때 보여줄 화면

현행은 "존재하지 않거나 비활성화된 홈페이지입니다" 한 장뿐이라, 만료된 중개사의 고객이
보면 폐업한 것처럼 보인다. 다음과 같이 분리한다.

| 상황 | 화면 | HTTP |
|------|------|------|
| 없는 주소 | 페이지를 찾을 수 없음 | 404 |
| 요금제 만료·수동 중지 | **일시적으로 중단된 페이지** 안내 + 공실뉴스 바로가기 | **503 + noindex** |

503으로 답해야 닫혀 있는 동안 검색 색인이 날아가지 않고, 재결제 시 검색 순위가 그대로
돌아온다. 404로 답하면 색인에서 제거된다.

### 4-4. 나중에 도메인을 사서 붙일 때

| 방식 | 내용 | 필요 작업 |
|------|------|-----------|
| **(A) 단순 포워딩** | 구입한 도메인을 DNS에서 서브도메인으로 넘김. 주소창에는 `{아이디}.gongsilnews.com`이 보인다 | **코드 변경 없음. 오늘도 가능** |
| **(B) 진짜 연결** | 주소창에 본인 도메인 유지, 검색도 본인 도메인으로 잡힘 | `custom_domain` 컬럼 + Vercel 도메인 등록 + middleware 수정 |

현행 middleware는 `.gongsilnews.com`만 잘라내므로(`middleware.ts:31`) 다른 도메인이
들어오면 주인을 못 찾는다. **이번에 `custom_domain` 칸과 조회 경로만 미리 깔아둔다.**
값이 비어 있으면 아무 일도 일어나지 않고, 나중에 (B)로 갈 때 페이지 코드는 손대지 않고
middleware와 Vercel 등록만 하면 된다.

### 4-5. ⚠️ 선행 확인 (코드 밖)

Vercel 프로젝트에 와일드카드 도메인 `*.gongsilnews.com`이 등록되어 있어야 한다.
개별 도메인만 등록된 상태라면 회원마다 수동 등록이 필요해 일괄 발급이 성립하지 않는다.

## 8. 모바일 홈페이지 관리 (2026-09-22 오후 회의)

### 8-1. 배경

홈페이지 편집은 지금 PC(`realty_admin?menu=homepage`)에서만 된다. 모바일 관리자
(`/m/admin/*`)에는 물건접수장 메뉴가 아예 없다. 중개사는 현장에서 폰으로 일하므로
사진 한 장 바꾸려고 사무실 PC 앞까지 가야 한다.

참고로 든 **AI 물건보고서 편집기**는 `marketing/report/`에 있는 **별도 Vite 앱**이다
(`App.tsx:1923`에 `◀ 보고서 편집 접기` 토글). Next 앱이 아니므로 코드는 가져올 수 없고
구조만 따른다.

### 8-2. 결정 사항

| # | 안건 | 결정 |
|---|------|------|
| 1 | 코드 구조 | **로직은 공유, 화면만 분리** — 불러오기·저장·업로드·슬라이드 조작을 훅 하나로 빼고 PC·모바일이 같이 쓴다 |
| 2 | 미리보기 | **상단 토글로 전환** — [▶ 편집 열기]면 입력 폼, [◀ 편집 접기]면 미리보기. 둘 중 하나만 그린다 |
| 3 | 하단 고정 버튼 | **저장하기 · 홈페이지 모바일로 보기 · 주소 복사** (PC로 보기는 제외) |
| 4 | PC와 연동 | 별도 장치 없음. 둘 다 `homepage_settings.design_settings` 한 곳을 읽고 쓴다 |

### 8-3. 구조

```
src/hooks/useHomepageEditor.ts          ← 공용 (불러오기·저장·사진·슬라이드·서브도메인 검사)
src/components/admin/sections/IntakeStudio.tsx   ← PC: 훅을 쓰도록 교체, 화면은 그대로
src/app/m/admin/homepage/page.tsx       ← 모바일: 같은 훅 + 폰 화면
```

모바일 화면 구성

- **상단 고정** — `‹` 뒤로 · "홈페이지 관리" · [▶ 편집 열기 / ◀ 편집 접기]
- **편집 모드** — 아코디언 5개(기본설정 · 디자인 · 섹션 · 접수항목 · 회사정보). PC와 같은 항목
- **미리보기 모드** — 실제 공개 컴포넌트(`SiteClient`)를 폰 폭으로 렌더
- **하단 고정** — [저장하기] 큰 버튼 + [모바일로 보기] + [주소 복사]
- 모바일 관리자 메뉴(`m/admin/dashboard/page.tsx`의 메뉴 배열)에
  `{ icon: "🏠", label: "물건접수장", href: "/m/admin/homepage", roles: ["realtor"] }` 추가

### 8-4. 과부하를 막는 지점

PC 편집기는 미리보기로 **실제 홈페이지 전체**(유튜브 iframe · 매물 사진 · 기사 목록)를
그대로 렌더한다. 폰에서 폼과 미리보기를 같이 띄우면 그게 그대로 부담이 된다.

- 미리보기 모드일 때만 `SiteClient`를 마운트한다. 편집 중에는 유튜브도 사진도 돌지 않는다
- 매물·기사 목록은 미리보기에 들어갈 때 한 번만 불러온다
- 사진은 지금처럼 올리기 전에 1280px WebP로 줄여 보낸다 (폰 사진 4~8MB → 0.2MB)

### 8-5. 남은 확인

- 편집 항목을 PC와 똑같이 다 넣을지, 폰에서는 자주 쓰는 것(첫 화면 사진·문구·섹션 on/off)만
  두고 나머지는 PC로 미룰지는 만들면서 화면 길이를 보고 정한다.

## 9. 고객문의(CRM) 및 접수 알림 (2026-09-22 오후 2차 회의)

### 9-1. 접수가 목록에서 사라지던 문제

중개사가 접수 알림을 받고 고객문의를 열었는데 목록에 없다는 제보로 시작했다.
DB를 열어보니 저장은 되어 있었다.

원인은 두 가지였다.

1. **같은 번호면 기존 고객에 합쳤다.** 합쳐진 건은 `created_at` 이 예전 그대로라,
   등록일 순 목록에서 몇 달 전 자리에 박혀 보이지 않았다.
2. 합칠 때 `name` 과 `type` 을 갱신하지 않아, 알림에는 새 이름·구해요가 뜨는데
   목록에는 옛 이름·내놔요로 남았다.

### 9-2. 결정 사항

| # | 안건 | 결정 |
|---|------|------|
| 1 | 같은 번호 재접수 | **합치지 않고 건별로 쌓는다.** 한 사람이 두 번 물었으면 두 번 응대할 일이다 |
| 2 | 2단계 폼 | 1걸음이 만든 건의 id 를 들고 가 2걸음이 거기에 붙는다. 한 번 접수 = 한 건, 알림도 한 번 |
| 3 | 목록 정렬 | `crm_logs` 의 마지막 기록을 "최근 문의"로 삼아 최신순. **DB 컬럼 추가 없음** |
| 4 | 목록 선택 | 체크박스 · 전체선택 · [선택삭제] (휴지통 탭에서는 영구삭제) |
| 5 | 접수 알림 | **관리자 화면 내 알림으로 유지.** 문자·알림톡은 붙이지 않는다 |
| 6 | 전화번호 중복 정리 | 이미 갈라진 기존 건은 건드리지 않는다 |

### 9-3. 접수 알림을 문자로 보내지 않기로 한 이유

붙일 수는 있었다 — 뿌리오 발송 코드(`src/utils/ppurio.ts`)와 고객에게 문자를
보내는 기능이 이미 돌고 있다. 다만 알림톡은 지금 보낼 수 없다.

```
PPURIO_KAKAO_SENDER_KEY    (비어 있음)
PPURIO_KAKAO_TEMPLATE_CODE (비어 있음)
```

키 이름만 있고 값이 없다. 알림톡을 쓰려면 카카오 채널 개설 → 발신프로필 등록 →
템플릿 심사(영업일 1~3일)를 거쳐야 하고, 승인된 문구만 나간다.

지금은 관리자 알림으로 충분하다고 보고 보류한다. 나중에 키가 준비되면 발송 수단만
갈아끼우면 된다.

### 9-4. 미룬 것

- **쿠키 도메인 확장** (`.gongsilnews.com`) — 이것이 풀려야 ①중개사 도메인에서 찜·댓글
  ②`admin` 버튼이 로그인 상태를 미리 판단 ③주인이 볼 때만 뜨는 홈페이지 관리 바가
  전부 가능해진다. 포털 인증을 건드리는 일이라 별도 안건으로 다룬다.
- 접수 알림 문자·알림톡
- 일시중지 화면(503·noindex), 주소 일괄 발급·백필, `custom_domain`
- 모바일 고객문의 선택삭제, 엑셀 다운로드 실제 동작

## 10. 인앱 브라우저에서 메뉴가 안 먹던 문제 (2026-09-22 저녁)

네이버 앱(안드로이드)으로 중개사 홈페이지를 열면 상단 메뉴를 눌러도 해당 섹션으로
가지 않았다. 사진 슬라이드는 넘어갔고 카드 탭도 됐다 — 스크립트는 살아 있었고
스크롤만 먹지 않았다.

### 원인

`src/app/globals.css` 의 이 한 줄이다.

```css
body { overflow-x: hidden; }
```

CSS 규칙상 한 축이 `visible` 이 아니면 다른 축은 `auto` 로 계산된다. 즉 body 가
스크롤 상자가 되고, 엔진에 따라 페이지의 스크롤 주체가 문서에서 body 로 옮겨간다.
그러면 앵커 이동도, `scrollIntoView` 도, 부드러운 스크롤도 붙잡을 대상이 없어진다.
데스크톱 크롬은 넘어가 주지만 안드로이드 웹뷰는 그대로 멈춘다.

### 고친 방법

중개사 홈페이지에서만 덮었다.

```css
html, body { overflow-x: clip; }   /* clip 은 스크롤 주체를 바꾸지 않는다 */
html { scroll-behavior: smooth; scroll-padding-top: 104px; }
```

더불어 메뉴를 진짜 링크(`<a href="#vacancy">`)로 바꾸고, 코드 경로도 한 방법에
기대지 않게 했다 — 스크롤 후 움직였는지 확인하고 안 움직였으면 옛 방식 →
`scrollTop` 직접 조작 → 주소 해시 순으로 넘어간다(`theme.ts`의 `scrollToSection`).

### 남은 위험

`globals.css` 는 전역이라 **포털 쪽에도 같은 함정이 남아 있다.** 모바일 페이지에서
앵커 이동이나 코드 스크롤을 쓰는 곳은 인앱 브라우저에서 같은 증상이 날 수 있다.
전역 수정은 사이트 전체에 영향이 가므로 별도 안건으로 다룬다.
