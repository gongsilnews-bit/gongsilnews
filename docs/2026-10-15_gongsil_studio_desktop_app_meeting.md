# 공실뉴스 스튜디오 (데스크톱 앱) 뼈대

- 회의일: 2026-10-15
- 상태: 뼈대 (세부 설계 전)

## 1. 한 줄 정의

회원 중개사가 PC에 설치하는 **윈도우 프로그램**이에요. 이 프로그램 하나에서 공실등록, 기사등록, SNS뉴스발행(자동화), 동영상제작, 고객관리를 모두 해요. 브루(Vrew)처럼 설치해서 쓰는 방식이에요.

## 2. 왜 만드나

- 지금은 크롬 확장에서 버튼을 한 단계씩 눌러야 하고, 마지막 등록도 사람이 해요.
- 회원이 **"관리자 화면에서 버튼 한 번"**으로 블로그·SNS·영상까지 끝내는 경험을 원해요.
- 참고 영상: https://www.youtube.com/watch?v=U5gu5r5qIgY
  - 웹 관리자 화면에서 작업을 지시하면, 사무실 PC의 "Windows 실행기"가 Playwright로 처리하는 구조예요.
  - 우리는 수많은 회원에게 나눠 줘야 해서 **실행기를 따로 두지 않아요.** 관리자 화면과 실행기를 앱 하나로 합쳐요.

## 3. 확정 사항

| 항목 | 결정 |
|---|---|
| 사용 대상 | 회원 중개사 (최고관리자 전용 아님) |
| 운영체제 | **윈도우 전용**, 맥은 만들지 않음 |
| 앱 형태 | Electron 데스크톱 앱 |
| DB | **지금 공실뉴스 DB(Supabase)를 그대로 씀.** 앱 전용 DB는 없음 |
| 크롬 확장 | 앱이 자리 잡을 때까지 유지하고, 그 뒤 앱으로 안내하며 정리 |
| FFmpeg | **설치 파일에 포함** (첫 EXE부터). 상업 배포가 가능한 라이선스 빌드를 씀 |
| 첫 EXE 범위 | 설치 파일, 앱 창(관리자 화면), 로그인 유지, 자동 업데이트, FFmpeg 포함 |
| 로그인 | **크롬 로그인을 넘겨받는 "클릭 한 번 연결"** (아래 5-1) |
| 코드 위치 | (권고) 저장소 안 `studio-app/` 폴더 (웹 배포와 분리) |
| 설치 파일 보관 | (권고) Supabase Storage (자동 업데이트도 여기서 받음) |

## 4. 메뉴 구성

| 메뉴 | 현재 | 앱에서 |
|---|---|---|
| 공실등록 | 있음 (`/realty_admin?menu=gongsil`) | 웹 화면 그대로 |
| 기사등록 | 있음 (`menu=article`) | 웹 화면 그대로 |
| 고객관리 | 있음 (`menu=customer`) | 웹 화면 그대로 |
| SNS뉴스발행 (자동화) | 확장에만 있음 | **새로 만듦, 앱 전용** |
| 동영상제작 | 릴스 계획만 있음 | **새로 만듦**, 웹과 앱 모두 |

- 웹에서 SNS뉴스발행을 누르면 "공실뉴스 스튜디오에서 이용하세요 + 다운로드"로 안내해요.

## 5. 구조

```
공실뉴스 스튜디오 (Electron, 윈도우)
├─ 메인 창: gongsilnews.com/realty_admin 을 불러옴 (로그인 공유)
├─ 자동화 엔진 (앱 안쪽)
│   ├─ 앱 안의 네이버·ChatGPT·Gemini·SNS 창 (회원이 한 번 로그인하면 유지)
│   ├─ 확장의 채우기 코드(content-naver.js 등)를 옮겨 와서 창을 조종
│   └─ 작업 대기열을 받아서 처리하고 결과를 서버로 보고
└─ 영상 엔진
    ├─ 편집 화면: 웹 릴스 편집 화면을 그대로 씀
    └─ 굽기: 서버(Vercel Sandbox)가 기본, 앱에서는 PC에서 직접 굽기 가능 (ffmpeg 포함)
```

### 5-1. 로그인: 클릭 한 번 연결 (확정)

구글은 앱 안에 띄운 창에서의 구글 로그인을 보안 정책으로 막아요(403 disallowed_useragent). 그래서 앱 창 안에서 로그인하지 않고, **회원 크롬에 이미 되어 있는 공실뉴스 로그인을 넘겨받아요.**

1. 앱을 처음 실행하면 크롬이 자동으로 열리고 `gongsilnews.com/studio/connect` 화면이 떠요.
2. "홍길동 소장님, 이 계정으로 스튜디오를 연결할까요?" 화면에서 **[공실뉴스 스튜디오 연결]**을 한 번 눌러요.
3. 앱으로 돌아오면 로그인이 끝나요. 크롬에서 앱으로는 `gongsilstudio://` 주소로 넘어와요.
4. 그 뒤로는 로그인 화면이 나오지 않아요. 회원이 직접 로그아웃하기 전까지 계속 유지돼요.

- 구글, 카카오, 네이버, 이메일 중 무엇으로 가입했든 똑같이 동작해요. 크롬에 로그인이 안 되어 있으면 크롬에서 평소처럼 로그인한 뒤 같은 버튼이 나와요.
- 안전장치
  - 연결 신호는 **5분 동안 한 번만** 쓸 수 있어요.
  - 웹 마이페이지에 **"연결된 PC 목록 / 연결 끊기"**를 둬요.
- 다시 연결하는 경우: PC를 바꾸거나 앱을 다시 설치했을 때만 한 번 더 해요.

### 작업 대기열 (확장과 앱이 함께 씀)

- 관리자 화면에서 작업 생성 → 대기 → 처리 중 → 확인 대기 → 완료 / 실패
- 관리자 화면에 "스튜디오 연결됨 / 끊김" 상태를 표시해요.
- 테이블과 API 설계는 다음 회의에서 정해요.

## 6. 원칙

- **네이버 블로그·SNS 발행 버튼은 회원이 누릅니다.** 자동 발행은 계정 제한 위험이 커서 하지 않아요.
- ChatGPT·네이버 **아이디와 비밀번호는 저장하지 않아요.** 회원이 앱 안의 창에서 직접 로그인하고, 그 로그인 상태만 PC에 남아요.
- 권한 판정은 서버가 해요. 지금 확장과 같은 규칙(`src/utils/extensionMember.ts`)을 써요.
- 영상 기능은 릴스 계획(사진 먼저, Gemini 성우, 공인중개사법 표시 항목 자동 삽입, 개인정보 차단)을 그대로 따라요.

## 7. 제작 순서

| 단계 | 내용 | 결과 |
|---|---|---|
| 1 | 앱 뼈대: 설치 파일(FFmpeg 포함), 자동 업데이트, 클릭 한 번 연결 로그인, 관리자 화면 불러오기 | 설치해서 쓰는 공실뉴스 |
| 2 | 작업 대기열 + **블로그 자동화** | 버튼 한 번에 블로그 초안 완성 (발행은 회원) |
| 3 | 동영상제작: 릴스 편집 화면 + 서버 굽기 | 웹과 앱에서 모두 릴스 제작 |
| 4 | 앱 전용 PC 굽기, 영상 클립 끼워 넣기 | 서버 비용 절감, 무거운 영상 처리 |
| 5 | SNS(인스타·페이스북·스레드), 정부24 등 자동화 확장 | |

## 7-1. 1단계 진행 (2026-10-15)

- 시험판은 서명 없이 사장님 PC에서만 써 봐요.
- `studio-app/`에 Electron 앱을 만들었어요.
  - 설치 파일: `npm run dist` → `dist/GongsilStudio-Setup-0.1.0.exe` (약 144MB)
  - FFmpeg 8.1 LGPL shared 빌드 포함 (x264 없음). MP4는 `h264_mf`(윈도우 내장)나 OpenH264로 만들어요.
- 웹에 연결 화면을 추가했어요: `/studio/connect`, `/studio/callback`, `/api/studio/connect`, `/api/studio/exchange`
  - 연결 신호에는 Supabase 매직링크 1회용 토큰이 AES-GCM으로 암호화되어 들어 있어요. 유효 시간은 5분이에요.
- 자동 업데이트 주소: Supabase Storage `studio-app/win/` (버킷은 아직 만들지 않았어요)
- 사장님 PC에서 설치하고 클릭 한 번 연결까지 성공했어요.
- 중개사 관리자(`/realty_admin`) 메뉴를 넓은 텍스트 메뉴로 바꿨어요(`StudioSidebar`).
  - 업무 6개: 대시보드, 공실등록, 기사등록, SNS뉴스발행, 동영상제작, 고객관리
  - 더보기 6개: 광고관리, 특강관리, 1:1문의, 포인트, 물건접수웹페이지, 매뉴얼
  - 앱에서 먼저 써 본 뒤 웹에도 켰어요(`STUDIO_MENU_ON_WEB = true`).
- 남은 일: 웹 배포 (완료), 사장님 PC에서 설치 시험, 업데이트 버킷 만들기, "연결된 PC 목록" 화면

## 7-2. 내 AI 연결과 블로그 작성 (2026-10-15 결정)

**내 AI 연결 (구독 계정 방식)**
- 목적: API 비용 없이 회원이 구독한 ChatGPT, Claude, Gemini로 글을 써요.
- **스튜디오 전용 크롬**: 앱이 회원 PC의 진짜 크롬을 별도 프로필로 띄워요. 구글 로그인이 막히지 않고, 평소 크롬과 분리돼요. 크롬이 없으면 엣지로 대신해요.
- ID와 비밀번호는 받지 않아요. 회원이 전용 크롬에서 각 AI에 직접 한 번 로그인하고, 로그인 상태는 그 PC에만 남아요.
- 위험 줄이기
  - 회원이 버튼을 누를 때만 한 건씩 작성해요.
  - 크롬 창을 화면에 보이게 띄우고, 사람처럼 속도를 조절해요.
  - 하루 사용량에 상한을 둬요.
  - 연결할 때 약관 위험에 동의를 받아요. Gemini는 업무용이 아닌 별도 구글 계정을 권해요.
- 순서: ChatGPT → Claude → Gemini
- 크롬 확장 코드(프롬프트, AI 입력·읽기, 네이버 붙여 넣기)를 앱으로 옮겨서 다시 써요. 확장 설치는 필요 없어요.

**블로그 작성 흐름**
1. 공실 선택 (앱의 공실 목록, DB에서 바로 읽음)
2. **공실 분석·캡처 (공통 1단계)**: 확장과 같은 사진을 모아요. 결과는 저장해 두고 기사, 블로그, SNS, 영상이 함께 써요.
   - 등록 사진 **전부**
   - **캡처 3장**: 공실열람 검증, 지도, 로드뷰
   - 앱이 안 보이는 창에서 찍어요.
3. 기사 쓰기와 블로그 쓰기 중 무엇이든 먼저 할 수 있어요. 블로그는 공실에서 바로 시작할 수 있고, 기사가 있으면 그것도 참고해요.
4. 네이버 블로그에 붙여 넣어요. 발행은 회원이 눌러요.

- 블로그 끝에는 출처 블록과 매물 상세 링크를 넣어요(지금 확장과 같음). **공실뉴스 기사 링크는 넣지 않아요.**
- 분석에 따른 추가 캡처(역세권 지도, 실거래가 차트 등)는 흐름이 안정된 뒤에 붙여요.

## 7-3. 뉴스칼럼 = 확장 뉴스메이커 (2026-10-15 결정)

- 뉴스·SNS발행 왼쪽 카테고리 "뉴스칼럼"에 확장 newsmaker10을 옮긴다. 이름은 "뉴스칼럼" 그대로.
- 소재는 나눠서 만든다: **1차 뉴스 + 주제 직접입력** (완료), 다음에 단지 시세·우리동네 시세(시세표 그림·지도 위치 포함).
- 뉴스 가져오기: 주소 붙여넣기(앱이 안 보이는 창에서 읽음) 또는 [네이버 뉴스 열기] → 전용 크롬에서 기사를 연 채 [지금 보는 뉴스 가져오기]. 가져온 원문은 고칠 수 있다.
- 소재를 정하면 칼럼 번호(col-…)가 생기고, 아래는 공실뉴스와 같은 탭(기사 → 블로그·SNS). 칼럼은 기사를 먼저 써야 블로그·SNS를 쓴다.
- 프롬프트는 확장 뉴스메이커 그대로(src/ext/newsmaker, sync-ext 로 복사): 원문 문장 옮기기 금지·출처 표기, 섹션은 AI가 고름(기사쓰기에 그대로 채움).
- 원문 사진은 쓰지 않는다. 기사를 쓰면 AI 대표 이미지를 자동으로 만든다(끌 수 있음, AI 이미지 하루 한도 안).
- 블로그 끝 [참고 자료](원문 언론사·제목·링크), SNS 끝 "출처: ○○ 보도 내용 재구성 · 공실뉴스".
- 이용 횟수: 기사는 등록할 때, 블로그·SNS는 공실뉴스와 같은 규칙(칼럼 하나 = 1회).
- 유튜브 대본은 나중에 동영상제작 메뉴로.
