# 공실뉴스 릴스 로컬 PC 편집기 아키텍처 회의

- 작성일: 2026-10-07
- 대상: 공실뉴스 릴스 제작 기능
- 상태: 설계 결정안

## 1. 회의 결론

공실뉴스 릴스 제작 기능은 모든 원본 영상을 서버에 먼저 업로드하는 웹 전용 편집기가 아니라, **서버와 사용자 로컬 PC가 역할을 나누는 하이브리드 구조**로 개발한다.

사용자가 직접 촬영한 장시간·대용량 원본 영상은 로컬 PC에 보관한다. 공실뉴스 서버는 로그인, 매물 정보, AI 대본, 음성·이미지 생성, 프로젝트 백업, 완성 영상 게시를 담당하고, 설치형 PC 편집기는 원본 영상 관리, 컷 편집, 미리보기, 자동 저장 및 최종 렌더링을 담당한다.

사용자는 공실뉴스에서 제공하는 Windows 설치 파일 하나만 실행한다. 설치 프로그램에는 편집기와 영상 제작에 필요한 `FFmpeg` 및 `FFprobe`를 함께 포함하여 별도의 수동 설치나 환경 변수 설정이 필요 없게 한다.

## 2. 설계 원칙

1. 장시간 원본 영상은 사용자의 로컬 PC에 둔다.
2. 원본 전체를 편집 전에 Supabase Storage로 업로드하지 않는다.
3. 편집 프로젝트는 로컬을 기준으로 자동 저장한다.
4. 서버에는 대본, 장면, 설정, 동기화 상태 등 작은 데이터만 저장한다.
5. AI 처리에는 원본 전체 대신 필요한 오디오, 저해상도 프록시 또는 샘플 프레임만 전송한다.
6. 최종 영상은 로컬 PC에서 렌더링한 후 완성본만 서버에 업로드한다.
7. Supabase 서비스 키와 서버 전용 비밀키는 데스크톱 앱에 포함하지 않는다.
8. 사용자가 별도로 FFmpeg를 설치하거나 시스템 `PATH`를 변경하지 않게 한다.

## 3. 전체 구조

```text
공실뉴스 웹/서버
├─ 회원 인증 및 권한 확인
├─ 매물 정보와 등록 사진 제공
├─ AI 릴스 대본 및 장면 구성
├─ 음성 인식과 AI 분석
├─ AI 성우·이미지·영상 생성
├─ 프로젝트 메타데이터 백업
└─ 완성 영상 저장 및 게시
             ↕ 인증된 API
공실뉴스 릴스 PC 편집기
├─ 로컬 원본 영상 불러오기
├─ 프록시·썸네일·파형 생성
├─ 컷·자막·효과 편집
├─ 로컬 프로젝트 자동 저장
├─ FFmpeg 기반 미리보기/렌더링
└─ 완성 MP4 업로드
```

## 4. 서버와 로컬 PC 역할

| 구분 | 공실뉴스 서버 | 로컬 PC 편집기 |
|---|---|---|
| 계정 | 로그인, 회원·매물 권한 검증 | 사용자 로그인 상태 유지 |
| 원본 영상 | 원칙적으로 보관하지 않음 | 원본 촬영 영상 보관 |
| 프로젝트 | 작은 동기화·복구용 데이터 저장 | 실제 편집 프로젝트와 자동 저장본 관리 |
| AI 대본 | 매물 정보를 바탕으로 초안 생성 | 대본 수정 및 장면에 배치 |
| 음성 인식 | 추출된 오디오 또는 필요한 구간 분석 | 원본에서 분석용 오디오 추출 |
| AI 미디어 | 성우, 이미지, 짧은 생성 영상 제작 | 결과물을 내려받아 타임라인에 배치 |
| 미리보기 | 담당하지 않음 | 로컬 영상으로 즉시 재생 |
| 최종 렌더링 | 렌더 요청·게시 상태 관리 | FFmpeg로 최종 MP4 생성 |
| 게시 | 완성본 저장, 매물·SNS 기능과 연결 | 완성된 파일만 업로드 |

## 5. 사용자 흐름

```text
1. 공실뉴스 웹에서 매물의 [릴스 만들기] 선택
2. 공실뉴스 릴스 PC 편집기 설치 여부 확인
3. 미설치 시 Windows 설치 파일 다운로드
4. 설치 완료 후 전용 링크로 편집기 실행
5. 일회용 인증 코드로 공실뉴스 계정과 연결
6. 매물 정보, 등록 사진, AI 초안을 서버에서 가져오기
7. 사용자가 PC에 있는 촬영 원본 영상 선택
8. 로컬에서 프록시와 썸네일 생성
9. 컷, 대본, 자막, 성우, 음악, 효과 편집
10. 프로젝트를 로컬에 계속 자동 저장
11. FFmpeg로 최종 세로형 MP4 렌더링
12. 완성 영상만 공실뉴스 서버에 업로드
13. 매물 페이지와 릴스 게시 기능에 연결
```

웹에서 데스크톱 앱을 열 때는 다음과 같은 전용 프로토콜 사용을 검토한다.

```text
gongsilreels://project/<project-id>?code=<one-time-code>
```

URL에는 장기 로그인 토큰이나 Supabase 서비스 키를 넣지 않는다. 짧은 만료 시간을 가진 일회용 코드만 전달하고, 데스크톱 앱이 서버에서 사용자 세션으로 교환한다.

## 6. Windows 설치 프로그램

### 6.1 목표 형태

```text
공실뉴스릴스-Setup.exe
        ↓ 한 번 설치
공실뉴스 릴스 앱
├─ gongsil-reels.exe
├─ ffmpeg.exe
├─ ffprobe.exe
├─ WebView2 구성요소 또는 설치 확인 기능
└─ 오픈소스 라이선스 고지
```

### 6.2 권장 기술

- 데스크톱 셸: Tauri 2
- UI: React 기반 전용 데스크톱 UI
- Windows 설치 파일: NSIS `setup.exe`
- 영상 분석·변환·렌더링: FFmpeg 및 FFprobe sidecar
- 로컬 저장: 프로젝트 폴더 + SQLite 또는 JSON 인덱스
- 자동 업데이트: 서명된 앱 업데이트 채널

현재 Next.js 웹 애플리케이션은 서버와 웹 관리 화면으로 유지한다. 데스크톱 편집기는 별도 `desktop/` 애플리케이션으로 구성하되, 공통 타입, 디자인 토큰 및 재사용 가능한 React 컴포넌트만 공유한다. Next.js 서버 전용 코드와 비밀키는 데스크톱 번들에 포함하지 않는다.

### 6.3 FFmpeg 포함 방식

FFmpeg를 시스템 전역에 설치하거나 Windows `PATH`에 등록하지 않는다. 앱 설치 폴더 안에 검증된 고정 버전을 포함하고, 데스크톱 앱이 해당 실행 파일의 절대 위치를 찾아 호출한다.

이 방식의 장점은 다음과 같다.

- 사용자에게 별도의 FFmpeg 설치를 요구하지 않는다.
- PC에 이미 존재하는 다른 FFmpeg와 충돌하지 않는다.
- 앱과 FFmpeg 버전을 함께 검증하고 업데이트할 수 있다.
- 렌더 결과의 재현성이 높아진다.
- 설치와 제거가 단순해진다.

앱 실행 시 `ffmpeg -version`과 `ffprobe -version`을 확인하고, 파일 누락·손상·지원 코덱 상태를 자체 진단한다.

## 7. 로컬 프로젝트 저장 구조

대용량 영상 바이너리를 브라우저 저장소나 데이터베이스 JSON에 넣지 않는다. 사용자가 프로젝트 폴더를 선택하거나 앱이 기본 프로젝트 폴더를 생성한다.

```text
공실뉴스 릴스 프로젝트/
├─ project.json              # 장면, 컷, 자막, 설정, 버전
├─ source-index.json         # 원본 파일명, 크기, 해시, 로컬 경로
├─ proxy/                    # 저해상도 편집용 프록시
├─ thumbnails/               # 장면 썸네일
├─ waveform/                 # 오디오 파형 데이터
├─ voice/                    # 내려받은 AI 성우 음성
├─ generated-media/          # AI 이미지·짧은 영상
├─ autosave/                 # 자동 저장과 복구본
└─ output/                   # 최종 MP4
```

### 원본 영상 식별

로컬 절대경로만 믿지 않는다. 원본마다 아래 정보를 함께 기록한다.

- 파일명
- 파일 크기
- 수정 시각
- 빠른 해시 또는 전체 해시
- 영상 길이, 해상도, 프레임률, 코덱
- 마지막으로 확인한 로컬 경로

파일이 이동되었을 때 사용자가 새 위치를 지정하면 해시를 비교하여 같은 원본인지 확인한다.

## 8. 프로젝트 저장과 동기화 원칙

로컬 프로젝트가 편집의 기준 원본이다. 서버는 다른 PC에서의 복구, 매물 연결 및 게시 상태 확인에 필요한 작은 스냅샷만 선택적으로 저장한다.

서버 동기화 대상:

- 프로젝트 ID와 매물 ID
- 프로젝트 스키마 버전
- AI 대본과 장면 목록
- 컷의 시작·종료 시각
- 자막, 강조, 스티커, 전환 효과
- 선택한 성우와 음악
- 로컬 원본의 파일명·크기·해시
- 프로젝트 리비전과 마지막 동기화 시각
- 완성 영상 ID와 게시 상태

서버에 저장하지 않을 항목:

- 로컬 절대경로
- 장시간 원본 영상 바이너리
- 프록시와 썸네일 캐시
- FFmpeg 임시 파일
- 사용자의 Supabase 세션 외 비밀키

동일 프로젝트가 두 PC에서 수정될 수 있으므로 `revision` 기반 낙관적 잠금을 적용하고, 충돌 시 자동 덮어쓰기하지 않는다.

## 9. 현재 `reel_projects` 마이그레이션 처리 방향

현재 파일:

```text
supabase/migrations/20261006_create_reel_projects.sql
```

현재 스키마는 서버 데이터베이스가 프로젝트의 중심이라는 전제를 가지고 있으므로 **그대로 확정하지 않는다**. 테이블은 원본 영상 저장소가 아니라 동기화·복구용 프로젝트 메타데이터 저장소로 재설계한다.

재설계 시 검토할 필드:

```text
id                 프로젝트 자체 ID
vacancy_id         연결된 매물
owner_member_id    프로젝트 소유 회원
last_edited_by     마지막 편집 회원
schema_version     로컬 project.json 형식 버전
revision           동시 저장 충돌 방지 버전
snapshot           동기화 가능한 작은 편집 데이터
source_manifest    원본 파일명·크기·해시 목록
desktop_app_version 마지막 저장 앱 버전
last_synced_at     마지막 동기화 시각
created_at
updated_at
```

매물당 프로젝트를 반드시 하나로 제한할지는 다시 결정한다. 한 매물에서 여러 버전의 릴스를 제작할 수 있으므로 장기적으로는 `vacancy_id`를 기본키로 사용하기보다 별도 `id`를 기본키로 두고 `vacancy_id`에 인덱스를 두는 구조가 더 유연하다.

## 10. `reel_jobs`, 음성 및 미디어 저장 방향

### `reel_jobs`

`reel_jobs`는 서버 렌더 전용 작업 큐가 아니라 다음 상태를 관리하는 공통 작업 기록으로 사용한다.

- AI 대본 생성
- 음성 인식
- AI 성우 생성
- AI 이미지·영상 생성
- 로컬 렌더 시작·완료·실패 보고
- 완성 영상 업로드 및 게시

각 작업에는 `execution_target`을 두어 `SERVER` 또는 `DESKTOP` 실행을 구분하는 방안을 검토한다.

### 음성 파일

AI 성우 음성은 서버에서 생성하고 Storage에 캐시할 수 있다. 데스크톱 앱은 해당 음성을 프로젝트의 `voice/` 폴더로 내려받아 반복 편집과 렌더링에 재사용한다.

### 생성 미디어

AI 이미지와 짧은 생성 영상은 서버에 원본을 보관할 수 있으며, 데스크톱 앱은 프로젝트에 필요한 파일만 내려받는다. 사용자가 직접 촬영한 장시간 영상과 생성 미디어를 동일한 저장 정책으로 다루지 않는다.

## 11. AI 분석 데이터 전송 최소화

장시간 원본 영상을 AI 처리 때문에 통째로 업로드하지 않는다.

용도별 전송 방식:

- 음성 인식: 오디오 트랙만 추출하여 전송
- 장면 분류: 일정 간격의 저해상도 프레임 전송
- 쇼츠 구간 추천: 저해상도 프록시 또는 분할 구간 전송
- 특정 장면 정밀 분석: 사용자가 선택한 짧은 구간만 전송
- 최종 게시: 완성된 MP4만 업로드

전송 파일에는 작업 ID와 만료 시간을 부여하고, 처리 완료 후 임시 원본을 삭제하는 정책을 둔다.

## 12. 렌더링 전략

1차 버전에서는 로컬 FFmpeg 렌더링을 기본으로 한다.

- 출력 기본 규격: 세로형 MP4, H.264/AAC, 1080×1920
- 소프트웨어 인코딩을 기본 안전망으로 제공
- NVIDIA NVENC, Intel Quick Sync, AMD AMF 지원 여부 자동 탐지
- 하드웨어 인코딩 실패 시 소프트웨어 인코딩으로 재시도
- 렌더 진행률, 남은 시간, 디스크 용량 표시
- 앱이 종료되어도 복구할 수 있도록 작업 상태 저장
- 렌더 완료 후 결과 영상 재생과 업로드 선택 제공

정확한 코덱 구성은 FFmpeg 배포 라이선스와 Windows 장치 호환성을 검토한 뒤 확정한다.

## 13. 보안 원칙

- 데스크톱 앱에 Supabase `service_role` 키를 포함하지 않는다.
- 사용자 세션 또는 짧은 만료 시간의 서명 URL만 사용한다.
- 웹에서 앱으로 전달되는 인증 코드는 일회용으로 만든다.
- FFmpeg 인자는 배열 형태로 구성하고 사용자 입력을 셸 명령 문자열에 직접 삽입하지 않는다.
- 서버가 내려주는 프로젝트 파일과 미디어의 크기·형식·해시를 검증한다.
- 앱 업데이트 파일과 설치 파일에 코드 서명을 적용한다.
- 자동 업데이트 매니페스트도 서명하고 HTTPS로 제공한다.

## 14. FFmpeg 배포 및 라이선스

FFmpeg는 기본적으로 LGPL이지만 빌드에 포함된 선택 라이브러리에 따라 GPL 또는 추가 조건이 적용될 수 있다. 특히 `libx264` 등 GPL 구성요소 포함 여부를 확인해야 한다.

배포 전 필수 작업:

1. 사용할 코덱과 FFmpeg 빌드 옵션을 확정한다.
2. 배포 바이너리를 재현할 수 있는 빌드 스크립트를 관리한다.
3. 바이너리와 정확히 일치하는 FFmpeg 소스와 빌드 설정을 제공한다.
4. 설치 프로그램, 앱 정보 화면 및 다운로드 페이지에 라이선스를 고지한다.
5. FFmpeg와 포함 라이브러리의 라이선스를 별도로 검토한다.
6. 상용 배포 전 법률 검토가 필요한 코덱 특허·라이선스 범위를 확인한다.

## 16. 1차 완료 기준

다음 조건을 만족하면 로컬 편집기 1차 버전을 완료한 것으로 본다.

- 사용자가 설치 파일 하나로 앱과 FFmpeg를 설치할 수 있다.
- 별도 환경 변수 설정 없이 FFmpeg가 실행된다.
- 1시간 이상의 로컬 원본 영상을 서버 업로드 없이 불러올 수 있다.
- 앱을 종료하고 다시 열어도 프로젝트가 복구된다.
- 원본 파일을 이동했을 때 새 위치를 다시 연결할 수 있다.
- 세로형 MP4를 로컬에서 렌더링할 수 있다.
- 완성 영상만 서버에 업로드할 수 있다.
- 서버 비밀키가 설치 파일과 로그에 포함되지 않는다.
- FFmpeg 라이선스 고지와 대응 소스 제공 절차가 마련되어 있다.

## 17. 후속 결정 사항

구현 시작 전에 아래 항목을 확정한다.

1. Windows 10과 Windows 11 중 최소 지원 버전
2. 프로젝트를 매물당 하나만 허용할지, 여러 버전을 허용할지
3. 로컬 프로젝트 저장 형식을 JSON 중심으로 할지 SQLite 중심으로 할지
4. 1차 버전에 자동 자막과 AI 장면 분석을 포함할지
5. LGPL 중심 FFmpeg 빌드를 사용할지, GPL 구성요소가 필요한지
6. 완성 영상을 자동 업로드할지 사용자가 확인 후 업로드할지
7. 클라우드 프로젝트 백업을 기본값으로 할지 선택 기능으로 둘지
